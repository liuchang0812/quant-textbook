Chapter 08 · 第三部 工程

回测
一台诚实的谎言机器

回测的唯一目的是证伪，不是证明。它的价值不在于告诉你「这个策略能赚多少」， 而在于告诉你「在什么条件下它会亏、亏多少、以及我的假设有多脆弱」。 这一章拆解回测里所有的作弊点，并给你一台尽量诚实的引擎。

有一个残酷的统计事实：只要你试的次数够多，任何随机策略都能回测出夏普 2。 回测框架不会阻止你，它会热情地配合你——你调一个参数，它给你一条更漂亮的曲线； 你再调一个，它更好。这个过程有强烈的多巴胺反馈，和打游戏升级一模一样。

所以一个成熟的量化研究者，对回测的态度是敌意的。他不是在问 「怎么让它更好看」，而是在问「我怎么才能证明它是假的」。这一章教你怎么当一个合格的敌人。

8.1回测的完整链条

一个诚实的回测，必须显式地走完这条链。任何一环被跳过，结果就不可信。

8.2向量化 vs 事件驱动

方式做法速度真实性适用
向量化用 pandas/numpy 一次性算完所有日期极快低（难以建模成本与约束）因子研究、快速筛选
事件驱动逐日/逐笔循环，模拟订单生命周期慢 10–100 倍高最终验证、实盘前

正确的工作流是：用向量化做研究，用事件驱动做验证。 向量化帮你快速排除 95% 的坏想法；事件驱动帮你确认剩下的 5% 里， 有多少是被成本杀死的。

向量化最大的坑

df["signal"].shift(1) 看起来解决了前视问题，但如果你在计算 signal 时 用了 df["close"].rolling(20).mean()，这个均值包含了当天收盘价—— 而你在当天收盘时是拿不到「收盘价」的（你要等到收盘那一刻）。 正确做法是 rolling(20).mean().shift(1)，或者明确约定「收盘后计算，次日开盘执行」。

8.3前视偏差的十种变体

我把常见的都列出来，建议做成 checklist，每次回测前过一遍。

  1. 用当日收盘价成交，而信号也用了当日收盘价。
  2. 用未来数据做标准化（全样本均值/方差）。
  3. 财报用报告期而非公布日。
  4. 用当前成分股回测历史。
  5. 用「今天是否 ST/退市」过滤历史样本。
  6. 参数在全样本上优化，然后报告全样本结果。
  7. 用未来的行业分类（公司后来改行了）。
  8. 用调整后的复权价挂单（价格现实中不存在）。
  9. 用「最高价/最低价」判断止盈止损顺序（不知道先后）。
  10. 在信号里用了当天收盘后才公布的公告。
最快的检测方法

把价格序列的日期随机打乱，重跑策略。如果还能赚钱，说明你的信号里有泄漏。 另一个方法：把策略的收益和「未来 1 日收益」做相关，如果相关性异常高（> 0.3）， 几乎可以确定有前视。

8.4成本建模：从「零成本」到「够真实」

成本模型不需要完美，但必须存在，并且保守。一个常用的分解：

总成本 = 佣金 + 税费 + 半价差 + 冲击 + 滑点 (8.1)
成本项典型值（A 股）建模方式
佣金0.01%–0.03%（双边）按成交额比例
印花税0.05%（仅卖出）按卖出额比例
过户费0.001%（双边）按成交额比例
半价差1–10 bps按标的流动性分层
冲击成本与订单量/成交量相关平方根模型（见第十章）

一个偷懒但有效的做法：先假设单边成本 20bps，跑一遍。 如果策略还能活，再细化模型；如果直接死了，说明它本来就很脆弱，不值得投入更多时间。

8.5成交假设：最容易被忽略的一段

「信号说买，回测就按收盘价买到了」——这是回测里最大的谎言。真实的成交需要回答：

  • 什么时候下单？收盘后？次日开盘？开盘后 30 分钟？
  • 用什么价格？开盘价、VWAP、还是限价单排队？
  • 能不能成交？涨停买不到，跌停卖不掉，停牌无法交易。
  • 成交多少？你的量占盘口多大比例？超过 10% 就会显著冲击。
fill_model.py
import numpy as np

def can_trade(row, side: str, limit_pct: float = 0.098) -> bool:
    """A 股涨跌停/停牌过滤。row 需含 open/high/low/close/prev_close/volume。"""
    if row["volume"] <= 0:
        return False                                  # 停牌
    ret = row["open"] / row["prev_close"] - 1
    if side == "buy" and ret >= limit_pct and row["high"] == row["low"]:
        return False                                  # 一字涨停，买不到
    if side == "sell" and ret <= -limit_pct and row["high"] == row["low"]:
        return False                                  # 一字跌停，卖不掉
    return True


def fill_price(open_price: float, side: str, spread_bps: float,
               impact_bps: float, slippage_bps: float) -> float:
    """在开盘价基础上，买方上浮、卖方下调。"""
    total = (spread_bps / 2 + impact_bps + slippage_bps) / 1e4
    return open_price * (1 + total) if side == "buy" else open_price * (1 - total)


def impact_bps(order_value: float, adv_value: float, coef: float = 10.0) -> float:
    """平方根冲击模型：成本 ∝ sqrt(订单占日均成交额比例)。"""
    if adv_value <= 0:
        return 999
    participation = order_value / adv_value
    return coef * np.sqrt(participation) * 100   # 转成 bps

8.6过拟合的数学：为什么「最优参数」是陷阱

假设你有 10 个参数，每个试 5 个值，组合空间是 5¹⁰ ≈ 976 万。 你不需要真的试完——遗传算法、网格搜索、甚至手动调参，都会把你推向 「在这段历史上最好」的那个点。而这个点，大概率是噪声的局部极值。

更 formal 地说：如果 N 个策略的真实夏普都是 0，那么最大夏普的期望约为 √(2 ln N) / √T（T 为年数）。试 100 个、5 年数据， 期望最大夏普约 1.36。这就是为什么「我试了 100 个策略，最好的夏普 1.5」 完全不能说明任何问题。

参数敏感性的正确用法

不要找「最优点」，要找「稳定的高原」。把参数网格画成热力图， 如果最优点周围一片绿（好），说明稳健；如果最优点是孤立的红点，周围全是蓝（差）， 那它是过拟合。宁可要一个平庸但稳定的参数，也不要一个优秀但脆弱的参数。

8.7样本外：Walk-Forward 与 Purged CV

Walk-Forward

把时间切成若干段：用前 3 年训练/选参，第 4 年测试；然后窗口向前滚动一年， 重复。最终把所有测试段拼起来，得到「样本外」的资金曲线。

Purged K-Fold 与 Embargo

如果策略的标签是「未来 20 日收益」，那么相邻样本的标签会重叠。 随机切分会让训练集和测试集共享同一段未来——这叫标签泄漏。

López de Prado 提出的解法是：在训练集和测试集之间挖掉一段 （purge），并额外留出一段缓冲（embargo），确保没有重叠。

purged_cv.py
import numpy as np

def purged_splits(n_samples: int, n_splits: int = 5,
                  label_horizon: int = 20, embargo: int = 5):
    """返回 (train_idx, test_idx)，训练集已剔除与测试集标签重叠的部分。"""
    indices = np.arange(n_samples)
    fold_size = n_samples // n_splits

    for k in range(n_splits):
        test_start = k * fold_size
        test_end = min((k + 1) * fold_size, n_samples)
        test_idx = indices[test_start:test_end]

        # 测试集标签会用到 test_end + horizon 的数据
        purge_end = min(test_end + label_horizon + embargo, n_samples)
        train_idx = np.concatenate([
            indices[:max(0, test_start - label_horizon)],
            indices[purge_end:],
        ])
        if len(train_idx) == 0:
            continue
        yield train_idx, test_idx

8.8动手：一台尽量诚实的回测器

下面这个引擎只有 100 多行，但它把该有的都做了：次日开盘成交、显式成本、 涨跌停过滤、逐日盯市。它的目标不是快，是让你无法自欺。

engine.py
from dataclasses import dataclass
import numpy as np
import pandas as pd


@dataclass
class Costs:
    commission: float = 0.0003     # 双边佣金
    stamp_tax: float = 0.0005      # 卖出印花税
    slippage: float = 0.0010       # 单边滑点（含半价差）


class Backtest:
    """极简事件驱动回测器。

    prices:  MultiIndex (date, symbol) 的 DataFrame，含 open/high/low/close/volume
    target:  MultiIndex (date, symbol) 的目标权重，date 为信号日（收盘后生成）
    """

    def __init__(self, prices: pd.DataFrame, target: pd.DataFrame,
                 capital: float = 1_000_000, costs: Costs = Costs(),
                 max_weight: float = 0.10, max_leverage: float = 1.0):
        self.px = prices.sort_index()
        self.target = target.sort_index()
        self.capital = capital
        self.costs = costs
        self.max_weight = max_weight
        self.max_leverage = max_leverage

    def run(self) -> pd.DataFrame:
        dates = self.px.index.get_level_values(0).unique().sort_values()
        symbols = self.px.index.get_level_values(1).unique()

        cash = self.capital
        shares = pd.Series(0.0, index=symbols)
        prev_close = pd.Series(np.nan, index=symbols)
        records = []
        traded_today = 0.0

        for i, date in enumerate(dates):
            day = self.px.loc[date].reindex(symbols)
            open_px = day["open"]
            close_px = day["close"]

            # ---- 1. 开盘：执行昨日信号 ----
            traded_today = 0.0
            if i > 0:
                prev_date = dates[i - 1]
                if prev_date in self.target.index.get_level_values(0):
                    w = self.target.loc[prev_date].reindex(symbols).fillna(0.0)
                    w = w.clip(-self.max_weight, self.max_weight)
                    if w.abs().sum() > self.max_leverage:
                        w *= self.max_leverage / w.abs().sum()

                    equity_open = cash + (shares * open_px.fillna(prev_close)).sum()
                    desired = (w * equity_open / open_px).replace([np.inf, -np.inf], np.nan)

                    for sym in symbols:
                        if not np.isfinite(open_px.get(sym, np.nan)) or open_px[sym] <= 0:
                            continue
                        if day.loc[sym, "volume"] <= 0:
                            continue
                        delta = desired.get(sym, 0) - shares[sym]
                        if abs(delta * open_px[sym]) < 1000:
                            continue

                        side = "buy" if delta > 0 else "sell"
                        px = open_px[sym] * (1 + self.costs.slippage * (1 if side == "buy" else -1))
                        fee = abs(delta * px) * (self.costs.commission +
                                                 (self.costs.stamp_tax if side == "sell" else 0))
                        cash -= delta * px + fee
                        shares[sym] += delta
                        traded_today += abs(delta * px)

            # ---- 2. 收盘：盯市 ----
            equity = cash + (shares * close_px.fillna(prev_close)).sum()
            gross = (shares * close_px.fillna(prev_close)).abs().sum()
            records.append({"date": date, "equity": equity, "cash": cash,
                            "gross": gross, "traded": traded_today})
            prev_close = close_px.combine_first(prev_close)

        out = pd.DataFrame(records).set_index("date")
        out["returns"] = out["equity"].pct_change().fillna(0)
        out["exposure"] = out["gross"] / out["equity"]
        out["turnover"] = out["traded"] / out["equity"]
        return out

这个引擎有几个刻意的设计，值得注意：

  • 信号日与执行日分离：target 在 T 日收盘生成，T+1 开盘执行。这一行代码消灭了 80% 的前视偏差。
  • 按开盘价重算股数：不是简单地按目标权重买入，而是用「当前权益 ÷ 开盘价」算目标股数，避免权重漂移。
  • 显式扣费：佣金、印花税、滑点分别计算，不混在一起。
  • 最小交易额过滤：< 1000 元的调仓不执行，避免不现实的碎股交易。
它仍然不完美

它没有模拟：部分成交、涨跌停无法成交、停牌、T+1 限制、以及冲击成本随订单量变化。 在生产环境里，这些都要补上。但即使只有这些，它已经比 90% 的「按收盘价全仓成交」 的回测诚实得多。

8.9一份回测报告应该长什么样

不要只给一条资金曲线。一份能让人信服的回测报告，至少包含：

基础指标

CAGR、年化波动、夏普、索提诺、最大回撤、卡玛、胜率、盈亏比、年化换手。

分年度收益

每一年的收益与回撤。如果收益集中在某一年，说明策略依赖特定环境。

成本敏感性

把单边成本从 0 调到 50bps，画一条「成本 → 夏普」的曲线。看它在哪一点归零。

参数敏感性

参数网格的热力图。最优点是否被「高原」包围？

归因

收益来自市场 beta、行业、风格，还是真正的选股？

极端情景

2015 股灾、2020 年 3 月、2022 年，策略分别发生了什么？

8.10陷阱清单

  • 用收盘价成交，且信号也用了收盘价。
  • 成本设为 0，或者只算佣金不算滑点。
  • 在全样本上调参，然后报告全样本结果。
  • 样本外只留最后 10%，且反复用它来「确认」。
  • 忽略涨跌停、停牌、T+1。
  • 用随机 K 折交叉验证处理时间序列。
  • 看到夏普 2 就兴奋，没有做参数敏感性和成本压力测试。
  • 回测报告只展示资金曲线，不展示分年度、不回撤、不归因。

本章练习

  1. 用 Backtest 跑一个简单的 20 日均线策略，然后分别把成本设为 0、10bps、30bps，观察夏普的衰减。
  2. 故意在信号里加入 shift(-1)，制造前视偏差，看夏普会虚高多少。这个数字就是「作弊的收益」。
  3. 把 Backtest 改成支持 T+1（当日买入次日才能卖），观察换手率高的策略受到什么影响。
  4. 为一个策略写一份完整的回测报告，包含 8.9 节的所有要素。

本章要点

  • 回测的目的是证伪；能杀死的策略越多，剩下的越可信。
  • 向量化做研究，事件驱动做验证；两者不能互相替代。
  • 前视偏差有十种常见变体，核心都是「时间戳错位」。
  • 成本必须显式建模并做压力测试；零成本回测没有意义。
  • 试 N 个策略的最大夏普期望约为 √(2 ln N)/√T，这就是过拟合的数学。
  • Walk-forward 与 Purged CV 是处理时间序列的正确方式。
