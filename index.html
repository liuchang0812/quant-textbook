Chapter 00 · 序

为什么程序员
适合做交易

不是因为你手速快，也不是因为你会写 Python。而是因为交易的核心能力—— 把模糊的直觉拆成可测量的变量、在噪声中做统计判断、对系统做工程化治理—— 恰好是程序员每天在训练的东西。这一章讲清楚三件事：市场到底在奖励什么， 这本书怎么读，以及你会踩的第一个坑。

阅读 12 分钟 难度 入门 代码 无

先讲一个反直觉的事实：在金融市场里，聪明不是稀缺资源，钱也不是。 真正稀缺的是「知道自己为什么赚钱」的能力。绝大多数亏损，不是因为不够聪明， 而是因为在一个自己没看懂的游戏里，用了一套无法解释的规则，赚到了几次运气钱， 然后把仓位加大了。

0.1市场在奖励什么

把市场想象成一台巨大的、持续运转的拍卖机。每一秒，都有成千上万的人对同一件东西 报出不同的价格。价格不是「价值」的直接读数，而是所有参与者用真金白银投票后的临时共识。 这个共识会犯错，会恐慌，会贪婪，但它有一个残酷的性质：它每天都在结算。

那么钱从哪里来？这是每个交易者必须回答的第一个问题。答案只有四类，没有第五类：

① 风险溢价 正和

你承担了别人不愿承担的风险，市场付你租金。股票长期跑赢现金、信用债跑赢国债、卖出保险收保费，都是这一类。它不需要你比别人聪明，只需要你能拿得住。

② 流动性提供 正和

别人急着成交，你提供对手盘，赚取买卖价差。做市商赚的就是这个。代价是库存风险和逆向选择——你买到的大多是别人想甩给你的。

③ 信息优势 零和

你知道别人不知道的事，或者更快地知道同样的事。从内幕交易到高频行情，本质都是信息差。对个人来说，这条路最窄。

④ 行为套利 零和

别人因为恐惧、贪婪、锚定、处置效应而错误定价，你站在对面。这是量化策略最主要的猎场，也是最容易被「市场变聪明」而失效的一类。

注意 ③ 和 ④ 标的是「零和」——扣除成本后甚至是负和。你赚的每一块钱，是另一个人亏的。 在这条赛道上，你必须持续证明自己比对手强，否则就是那个被收割的人。 而 ① 和 ② 是正和的：市场整体在创造价值，你只需要正确地承担风险。

核心认知

初学者最常犯的战略错误，是一头扎进 ③④ 的零和博弈，却用 ① 的心态（「长期拿着总会涨」）来管理仓位。 这两套逻辑的风险管理方式完全相反：前者要求严格止损、快速证伪；后者要求承受波动、拒绝频繁交易。 先想清楚你在赚哪一类钱，再谈策略。

0.2程序员的三件武器，和一个致命弱点

你比大多数散户有优势，但这个优势不在你以为的地方。

武器一：可复现性

程序员天生不信任「我感觉」。你会要求一个结果能被重跑，能定位到输入、参数和版本。 这在交易里极其珍贵——因为交易最擅长的就是制造「这次不一样」的幻觉。 一个能复现的回测框架，是你对抗自我欺骗的唯一工具。

武器二：把想法变成可测量的东西

「低估值股票会跑赢」是一句废话，除非你能定义什么叫低估值（PE 倒数？EV/EBITDA？行业内分位？）， 怎么分组，持有多久，怎么加权，扣多少成本。定义即策略。 把模糊叙事翻译成可执行规格，这是程序员的日常。

武器三：对复杂系统的耐受

你会调试一个偶发的空指针，会追一条跨五个服务的调用链。交易系统同样是复杂系统： 数据延迟、部分成交、断线重连、状态不一致。大多数交易者是被这些「工程细节」杀死的，不是被行情。

致命弱点

程序员最大的陷阱是把「能跑通」当成「有效」。代码跑出漂亮的资金曲线， 多巴胺立刻奖励你——这和产品上线拿到数据的感觉一模一样。但回测不是产品验证， 回测是一个可以被无限次调参直到好看的系统。你越擅长写代码， 越容易在几小时内生成几百个「年化 40%」的策略，然后全部是过拟合。 这本书的第三部，有一半篇幅在教你怎么杀死自己的策略。

0.4三个必须先接受的残酷事实

事实一：你大概率会亏钱，而且不是因为笨

学术研究反复发现，活跃交易者的净收益分布在扣除成本后显著为负。这不是能力问题，是结构问题： 你面对的是全职机构、低延迟基础设施、以及一个专门设计来让你频繁交易的界面。 接受这一点，你才会认真对待成本、仓位和证伪——而不是急着找一个「圣杯指标」。

事实二：收益是非线性的，而你的直觉是线性的

大多数人以为「年化 20%」意味着每年稳稳赚 20%。真实情况是：某年 +55%，某年 −28%， 有两年几乎不赚，还有一次连续 14 个月的回撤让你怀疑人生。 你真正要管理的不是收益，是「在坏年份活下来」的概率。

事实三：知道和做到之间，隔着一条叫「仓位」的河

你可以完全理解凯利公式，然后在账户回撤 20% 的那个晚上，把所有仓位砍在最低点。 知识不改变行为，流程才改变行为。所以这本书会反复讲规则、清单、日志—— 这些东西看起来不性感，但它们是唯一能在压力下生效的东西。

交易不是预测未来的游戏，是在不确定性中持续做出正期望决策的游戏。 前者需要神，后者需要工程师。

0.5开始之前，先做一件事

拿出一张纸（或一个文本文件），写下三行：

  1. 我为什么想学交易？（想赚钱 / 想理解市场 / 想找刺激 / 职业转型）
  2. 我能承受的最大亏损是多少？具体到金额，以及「亏到这个数我会睡不着吗」。
  3. 我每周能投入多少小时？

这三个答案会决定你该走哪条路。如果答案是「想找刺激」，那交易对你来说是一种昂贵的娱乐， 请把预算控制在娱乐开支里。如果答案是「想理解市场」，那你会享受这本书，并且大概率能活得不错。 如果答案是「职业转型」，那么第三部的工程能力比第二部的策略灵感重要十倍。

一句话

「市场保持非理性的时间，可以比你保持不破产的时间更长。」——这句话的重点不是市场，是「不破产」。

本章练习

  1. 列出你过去（或想象中）最想买的三个标的，写下你买它的理由。然后问自己：这个理由属于 0.1 节的哪一类？
  2. 找一个你听说过的「稳赚策略」（朋友推荐、短视频、付费课都行），尝试用一句话指出它的收益来源。如果指不出来，记下它，读完第一部再回来回答。
  3. 写下你的「最大可承受亏损」金额，以及对应的账户总资金。算出这个比例——它会是你后面所有仓位规则的边界。

本章要点

  • 市场只付四种钱：风险溢价、流动性提供、信息优势、行为套利。前两种正和，后两种零和。
  • 程序员的优势是可复现、可定义、能处理复杂系统；弱点是容易把「跑通」当「有效」。
  • 亏损的主因通常不是智商，而是不知道自己在赚哪类钱、以及仓位管理失控。
  • 你要管理的是「活下来的概率」，不是「收益的最大值」。
Chapter 01 · 第一部 地基

市场是什么
从撮合引擎说起

把 K 线图关掉。市场真正的样子，是一个不断接收订单、按价格优先时间优先排序、 逐笔撮合的有限状态机。理解这台机器怎么工作，你才会明白：为什么你的回测成交价是假的， 为什么大单会把价格推上去，以及为什么「流动性」是一个可以定价的东西。

阅读 26 分钟 难度 入门 代码 撮合引擎

几乎所有人第一次接触市场，看到的都是一张 K 线图：红红绿绿的柱子，上下影线， 均线交叉。这张图很有说服力，以至于人们忘了它是二手信息—— 它是把无数笔真实交易压缩、平滑、抽象之后的结果。就像你看一张城市交通热力图， 能看到拥堵，但看不到红绿灯的配时逻辑。

而交易的成本、成交的可能性、策略的容量，全部藏在那台被抽象掉的机器里。 这一章我们把它拆开。

1.1交易所的本质：一本不断变动的账

现代交易所的核心数据结构简单得令人失望：两个按价格排序的队列。 一个叫买盘（bid），一个叫卖盘（ask）。每个队列里是一张张限价单， 每张单子写着「我愿意用 X 价格买/卖 N 股」。

当一张新订单进来，撮合引擎做三件事：

  1. 能不能立刻成交？如果是买单，看卖盘最低价是否 ≤ 你的出价。能，就成交。
  2. 成交多少？取双方数量的较小值。剩余部分继续找下一个价位。
  3. 成交不完怎么办？如果是限价单，剩下的挂在买盘队列里排队；如果是市价单，剩下的撤销或按配置处理。

就这么多。没有魔法，没有庄家操盘的黑箱（至少在这一层没有）。 你看到的每一次价格跳动，都是这个循环的输出。

关键洞察

价格不是「算」出来的，是撮合出来的。这意味着价格的每一次变化， 都必须有一笔真实的成交作为代价。想让价格涨 1%，需要有足够多的买单把卖盘从当前价一路吃上去。 这个「吃」的过程有成本，成本的大小取决于盘口有多厚——这就是流动性。

1.2盘口：价格是分层的信息

如果你只能看一个数字，你看最新成交价。如果你能看十个数字，你看盘口（order book）。 盘口告诉你在每个价位上，有多少人愿意交易。

这张图里有三个信息，K 线永远不会告诉你：

  • 价差（spread）：100.50 − 100.40 = 0.10，约 10 个基点。这是你每次「往返交易」的固定门票。
  • 深度（depth）：卖盘前三档一共 12,300 股。你想买 20,000 股，就必然吃到 100.55 以上。
  • 不对称性：买盘比卖盘薄，说明当前买方更急，或者卖方更惜售。这是极短周期的信号来源之一。

常见错误

很多人用「止损单」来管理风险，却不知道止损单在流动性枯竭时是最危险的订单类型： 它会在最坏的时刻变成市价单，和所有其他止损单一起涌向同一个方向。 2020 年 3 月、2024 年 8 月日经暴跌，都出现过止损单连环触发的流动性真空。 止损应该是一个「决策」，不是一个「挂单」。

1.4价格不是连续函数

这是程序员最容易建立、也最容易被忽略的直觉。数学上我们习惯把价格写成 P(t)， 一条光滑曲线。但真实的价格是一个分段常数函数，只在成交发生的瞬间跳变。

更麻烦的是，成交在时间上极度不均匀。一只股票一天可能有几万笔成交， 但其中 80% 集中在开盘和收盘的几十分钟。中午可能几分钟都没有一笔。 如果你按「每 5 分钟一根 K 线」来建模，你实际上是在用时间采样去近似一个事件驱动的过程， 这中间的信息损失，就是很多策略「回测很好、实盘不灵」的原因之一。

1.5摩擦：四种你必然支付的成本

交易不是免费的。每一笔往返交易，你都在向系统支付四笔钱，它们决定了策略的「最低收益率门槛」。

价差成本

跨过买卖价差。流动性好的大盘股约 1–3 bps，小盘股可能 20–50 bps。日内策略的最大杀手。

佣金与税费

券商佣金、交易所规费、印花税（A 股卖出 0.05%）、过户费。低频策略里占比小，高频里致命。

冲击成本

你的订单改变了价格。下单量越大、越快，冲击越大。近似与 √(Q/V) 成正比。

时机风险

为了减少冲击而拆单慢买，价格却在你等待时跑掉了。执行的本质是在冲击与时机之间求最优。

把这几项加起来，一个日频换手 20% 的策略，年化成本可能高达 3–8%。这意味着： 如果你的毛 alpha 只有 5%，你其实在亏钱。第十章会专门讲怎么测量和优化它。

这一点极其重要，却极少有人讲。你每一次成交，对面都有一个具体的人或机器。 知道对手是谁，你才知道自己凭什么赢。

  • 做市商：提供双边报价，赚价差。他们最怕有毒订单流（informed flow）。
  • 高频交易者：赚微观结构里的微小价差和延迟优势。速度上你不可能赢。
  • 量化基金：中频统计套利、因子投资。比的是数据、模型和成本控制。
  • 公募 / 保险 / 养老金：体量大、周期长，常常是流动性的提供者，也是「被迫交易者」。
  • 散户：情绪化、追涨杀跌、止损集中。行为套利的猎物，但也是彼此最大的对手。

如果你做日频因子策略，你的对手主要是其他量化基金和情绪化散户；如果你做日内， 对手是做市商和高频。前者比的是想法和纪律，后者比的是基础设施。 作为个人，选前者。

1.8动手：写一个极简撮合引擎

不到 80 行，你就能拥有一台真实运行的市场。这段代码值得逐行读——它会把「价格是怎么来的」 从抽象概念变成你能调试的东西。

matching_engine.py
from dataclasses import dataclass, field
from enum import Enum
from collections import deque
import itertools


class Side(Enum):
    BUY = "buy"
    SELL = "sell"


@dataclass
class Order:
    side: Side
    price: float
    qty: int
    seq: int = field(default_factory=itertools.count().__next__)
    filled: int = 0


class OrderBook:
    """价格优先、时间优先的连续撮合。"""

    def __init__(self):
        # 价格 -> 该价位的订单队列（FIFO 保证时间优先）
        self.bids: dict[float, deque] = {}
        self.asks: dict[float, deque] = {}
        self.trades: list[tuple[float, int]] = []

    def _best_bid(self):
        return max(self.bids) if self.bids else None

    def _best_ask(self):
        return min(self.asks) if self.asks else None

    def submit(self, order: Order) -> list[tuple[float, int]]:
        """提交订单，返回本次产生的成交列表 [(price, qty), ...]"""
        book = self.asks if order.side is Side.BUY else self.bids
        opposite = self._best_ask if order.side is Side.BUY else self._best_bid
        fills = []

        while order.qty > order.filled and opposite is not None:
            # 价格是否还能成交：买单要 >= 卖一，卖单要 <= 买一
            if order.side is Side.BUY and order.price < opposite:
                break
            if order.side is Side.SELL and order.price > opposite:
                break

            queue = book[opposite]
            resting = queue[0]
            deal = min(order.qty - order.filled, resting.qty - resting.filled)

            resting.filled += deal
            order.filled += deal
            fills.append((opposite, deal))
            self.trades.append((opposite, deal))

            if resting.filled == resting.qty:
                queue.popleft()
                if not queue:
                    del book[opposite]

            opposite = self._best_ask if order.side is Side.BUY else self._best_bid

        # 限价单剩余部分挂队
        if order.filled < order.qty:
            self._rest(order)
        return fills

    def _rest(self, order: Order):
        book = self.bids if order.side is Side.BUY else self.asks
        book.setdefault(order.price, deque()).append(order)

    def snapshot(self, depth: int = 3) -> dict:
        bids = sorted(self.bids.items(), key=lambda kv: -kv[0])[:depth]
        asks = sorted(self.asks.items(), key=lambda kv: kv[0])[:depth]
        return {
            "bids": [(p, sum(o.qty - o.filled for o in q)) for p, q in bids],
            "asks": [(p, sum(o.qty - o.filled for o in q)) for p, q in asks],
        }

赌场为什么永远赚钱？不是因为每一把都赢——轮盘赌的庄家优势只有 2.7%， 意味着你下注 100 块，长期平均只亏 2.7 块。它赚钱是因为它玩了上百万把， 而且它的资金量足以承受任何短期波动。这两点，恰好是散户做不到的： 玩得不够多，资金不够厚，还在用错误的仓位。

这一章要给你两样东西：一个判断「这笔交易值不值得做」的公式， 和一个判断「该下多大注」的公式。前者叫期望值，后者叫凯利。

2.1期望值：把「感觉」变成算术

假设一个策略：胜率 40%，赢的时候平均赚 2R，输的时候平均亏 1R。 这里的 R 是「一个风险单位」——你每笔交易愿意亏的钱。 用 R 来计量，可以把不同价格、不同标的的交易放在同一把尺子上比较。

E = p · W − (1 − p) · L (2.1)

p 为胜率，W 为平均盈利（R），L 为平均亏损（R）。E 是每笔交易的期望收益，单位也是 R。

代入数字：E = 0.4 × 2 − 0.6 × 1 = 0.2R。 意思是：平均每做一笔，你赚 0.2 个风险单位。如果你每笔风险 1000 元，做 1000 笔，期望赚 20 万。

注意这个策略的胜率只有 40%——大部分时间是错的。这正是趋势跟踪的典型画像： 十次里错六次，但对的两次赚得足够多。胜率和期望值是两件独立的事， 而人类的大脑天生偏爱高胜率，这让我们系统性地高估了「经常对」的价值。

盈亏平衡胜率

令 E = 0，解出 p：

p* = L / (W + L) (2.2)

当 W = 2R、L = 1R 时，p* = 33.3%。你的胜率必须高于 33.3% 才不亏。 如果盈亏比降到 1:1，p* 就变成 50%——再扣掉交易成本，你需要 55% 以上才能赚钱。 这就是为什么「高胜率小止盈 + 大止损」的策略看起来很美，实际是慢性自杀： 它把 p 推得很高，但把 W/L 压到 0.3，p* 变成 77%，长期必然爆掉。

最容易被忽略的除法

高频策略的生死线不是「胜率」，而是 平均盈利 ÷ 单笔成本。 如果你的平均盈利是 0.3R，成本是 0.25R，那么成本吃掉了 83% 的毛利。 此时任何微小的成本估计误差（比如滑点从 2bps 变成 4bps），都会让策略由正转负。 毛 alpha 越薄，对成本建模精度的要求越苛刻。

2.2凯利公式：该下多大注

知道期望值为正，只解决了「做不做」。接下来是「做多大」，而这个问题的答案， 决定了你是慢慢变富还是快速归零。

1956 年，贝尔实验室的 John Kelly 在研究信息论时给出了答案。假设你可以无限次重复一个 赔率为 b（赢时赚 b 倍下注额，输时亏掉下注额）、胜率为 p 的赌局，那么使长期资金增长率最大化的下注比例是：

f* = p − (1 − p) / b  =  (p·b − (1−p)) / b (2.3)

用 2.1 节的例子：p = 0.4，b = 2，则 f* = 0.4 − 0.6/2 = 0.1。 也就是每次投入总资金的 10%。

这个公式有三个惊人的性质，每一个都值得你停下来想一会儿：

  1. 它自动惩罚低胜率。p 低于 1/(1+b) 时，f* 为负——意思是这个赌局根本不该参加。
  2. 它对参数极度敏感。p 从 0.4 估成 0.45，f* 就从 0.10 跳到 0.175，仓位翻了 75%。而你的胜率估计误差，通常远大于 5%。
  3. 超过 2f* 必死。下注比例超过凯利值的两倍，长期增长率转为负——哪怕每一注都是正期望。

连续版本：更实用的形式

股票和期货不是离散赌局，收益是连续的。连续时间下的凯利公式简洁得惊人：

f* = μ / σ² (2.4)

μ 为预期超额收益（年化），σ 为波动率（年化）。注意分母是方差，不是标准差。

假设一个策略年化超额 10%，波动率 20%，则 f* = 0.10 / 0.04 = 2.5。 这意味着理论上可以用 2.5 倍杠杆。但现实中没人这么做，原因见下一节。

为什么实战要用「半凯利」甚至「四分之一凯利」

凯利公式假设你精确知道 p 和 b。现实中你不知道，你只有估计值， 而估计值有误差。误差在凯利公式里会被放大：仓位对 μ 是线性的，对 σ 是平方反比的。 更糟的是，凯利策略的回撤可以非常深——理论上，全凯利下注有约 50% 的概率经历 一次超过 50% 的回撤。你确定你的心理和资金结构能承受吗？

工程化建议

用 1/4 凯利起步。它只牺牲约 25% 的长期增长率，却把回撤降到大约一半。 对于参数不确定的策略，这是性价比最高的选择。等策略跑满两年、样本足够， 再考虑往 1/2 凯利靠。

2.3波动拖累：为什么杠杆会偷走你的收益

假设一个策略第一年 +50%，第二年 −50%。你的直觉可能是「不赚不亏」。 但实际账户是：1 × 1.5 × 0.5 = 0.75，亏了 25%。

这不是算术错误，这是几何收益与算术收益的区别。长期资金的增长由几何平均决定， 而几何平均总是小于算术平均，差距约等于方差的一半：

g ≈ μ − σ² / 2 (2.5)

这个 σ²/2 叫波动拖累（volatility drag）。 波动率 20% 时，它每年吃掉 2%；波动率 40% 时，吃掉 8%；波动率 80% 时，吃掉 32%。 这就是为什么 3 倍杠杆的 ETF 长期表现远差于「指数涨 3 倍」—— 杠杆同时放大了 μ 和 σ，而 σ² 项增长得更快。

一个反直觉的推论

如果你有两个策略，年化收益都是 10%，一个波动 10%，一个波动 30%， 那么前者的长期复利增长是 9.5%，后者只有 5.5%。降低波动本身就是一种 alpha， 而且它不需要你预测得更准。这就是风险平价、波动率目标化这类技术的理论基础。

2.4破产：那个不可逆的状态

期望值为正、仓位合理，你仍然可能破产——只要玩得足够久，且每次下注是总资金的固定比例。 因为资金是一条有吸收壁的随机游走：一旦触到 0，游戏结束，之后所有的正期望都与你无关。

对于固定比例下注，破产概率有一个经典近似（risk of ruin）：

P(ruin) ≈ ((1 − e) / (1 + e))N (2.6)

e 为每单位的期望优势（edge），N 为你能承受的连续亏损单位数。公式是启发式的，但方向是对的：N 越大，破产概率指数级下降。

这个公式最重要的含义不是精确计算，而是：把「能承受多少次连续亏损」当成一个设计参数。 如果你的策略历史最大连亏是 8 次，你应该设计成能承受 20 次。 这不是保守，这是给「历史样本之外」留出空间。

2.6把 R 变成可执行的东西

到目前为止我们一直在用 R 这个抽象单位。落地时，它必须变成具体的股数和金额。 最常用的方法是基于波动率的仓位：

仓位（股数） = (账户资金 × 单笔风险%) / (止损距离 × 每股价值) (2.7)

假设账户 100 万，单笔风险 1%（1 万元），股票现价 50 元，你用 2×ATR 作为止损距离， ATR = 1.5 元，则止损距离 = 3 元。仓位 = 10000 / 3 ≈ 3333 股，市值约 16.7 万， 占总资金 16.7%。

这个公式的美妙之处在于：它让每一笔交易的风险都相同。 波动大的股票自动买得少，波动小的自动买得多。你的资金曲线因此变得平滑， 而平滑的资金曲线意味着更小的波动拖累、更低的破产概率、以及更稳定的心理状态。

注意止损距离的陷阱

止损距离不能拍脑袋。太近，你会被正常波动反复扫出（胜率暴跌）；太远，单笔亏损过大。 常用做法是用 ATR 的 1.5–3 倍，或者用结构位（前低、支撑）加一点缓冲。 更重要的是：先定止损，再算仓位。反过来（先决定买多少，再看能亏多少）是散户最典型的错误。

2.7本章陷阱清单

  • 用胜率评价策略。胜率 90% 的策略可能每笔赚 1 块、亏 20 块。
  • 把「期望值为正」当成「可以满仓」。期望值决定方向，仓位决定生死。
  • 用全凯利。你估计的参数一定有误差，而凯利对误差极度敏感。
  • 忽略波动拖累，以为 2 倍杠杆就是 2 倍收益。
  • 先决定买多少，再想止损在哪。
  • 用「连续亏损次数」的样本内最大值来设定风险预算，而不留安全边际。

收益的语言

「年化 30%」这句话几乎没有任何信息量。它可能是稳定复利，也可能是三年里两年亏、 一年翻倍。要判断一个策略的好坏，你需要一套精确的语言：简单收益与对数收益的区别、 三种年化的陷阱、夏普比率在衡量什么、最大回撤为什么比收益更值得关注。 这一章建立你的度量衡。

阅读 30 分钟 难度 中级 代码 指标库

在工程里，如果你不能用数字描述一个系统的行为，你就无法优化它。 交易也一样。但交易的麻烦在于：几乎所有直观的指标都会骗人。 收益率会被少数几笔极端交易扭曲，波动率会把上涨和下跌同等对待， 夏普比率假设收益服从正态分布——而市场最不缺的就是不服从正态分布的时刻。

所以这一章的目的不是给你一堆公式，而是让你知道每个数字在什么情况下会撒谎。

3.1简单收益与对数收益

假设一只股票从 100 涨到 120，再跌回 100。简单收益是 +20% 和 −16.67%， 算术平均 +1.67%——但你一分钱没赚。问题出在：简单收益不能相加。

对数收益（log return）解决了这个问题。定义 r = ln(P₁/P₀)， 则上涨时 r = ln(1.2) = 0.1823，下跌时 r = ln(0.8333) = −0.1823，相加正好为 0。

rlog = ln(1 + rsimple)   ⇔   rsimple = erlog − 1 (3.1)

两者的分工非常明确：

场景用哪个原因
跨期累加对数收益可加性：多期总收益 = 各期对数收益之和
跨资产加总简单收益组合收益 = 各资产收益的加权和（对数收益不成立）
统计建模对数收益更接近对称分布，方差更稳定
向人汇报简单收益「赚了 20%」比「对数收益 0.182」直观
小收益率下可以近似

当 r 很小时，ln(1+r) ≈ r − r²/2，两者几乎相等。 日收益 ±2% 以内，用哪个都行。但当你计算多年累计收益、或者处理高波动资产（比如加密货币）时， 差异会变得巨大：年化 100% 的简单收益，对应 69.3% 的对数收益。

3.2年化：三种平均，三个答案

假设一个策略四年的收益是：+50%、−20%、+30%、+10%。它的「年化收益」是多少？ 答案是：取决于你问谁。

算术平均

(0.5 − 0.2 + 0.3 + 0.1) / 4 = 17.5%

这是最乐观的答案，也是基金销售最爱用的。但它对应的是「每年都把收益取出来」的假设， 不代表你的资金实际增长。

几何平均（CAGR）

[(1.5)(0.8)(1.3)(1.1)]1/4 − 1 = 14.5% (3.2)

这才是你账户真实的年化复合增长率。它永远小于等于算术平均，差距随波动率增大。 任何严肃的策略评价都应该用 CAGR。

对数平均

exp( mean(ln(1+rt)) ) − 1 = 14.5%

与 CAGR 完全等价（数学上恒等）。它好在可以直接用日频数据计算，不必等到期末。

记住这个不等式

算术平均 ≥ 几何平均 ≥ 中位数（对右偏分布）。 当有人告诉你「平均年化 20%」，你要问的第一句话是：「算术还是几何？」 第二句是：「最大回撤多少？」

3.3波动率：风险的第一个近似

波动率就是收益率的标准差，通常按年化表示：

σ年 = σ日 × √252 (3.3)

252 是一年的交易日数（A 股约 242，美股约 252，加密资产 365）。 这个 √T 缩放来自「独立同分布」假设——它在大样本下近似成立， 但在极端行情里会失效，因为波动率本身是聚集的（volatility clustering）。

波动率不是恒定的

这是新手最容易忽略的一点：波动率会「抱团」。大波动后面跟着大波动，平静后面跟着平静。 这就是 GARCH 模型要刻画的现象。实践含义是：

  • 用过去 20 天的波动率预测明天，比用过去 3 年更准。
  • 但短窗口噪声大，所以通常用 EWMA（指数加权）折中。
  • 当波动率突然翻倍时，你的仓位应该自动减半——这就是波动率目标化。
volatility.py
import numpy as np
import pandas as pd


def ewma_vol(returns: pd.Series, halflife: int = 20) -> pd.Series:
    """指数加权波动率（日频）。halflife 越小，对近期变化越敏感。"""
    return returns.ewm(halflife=halflife, adjust=False).std() * np.sqrt(252)


def realized_vol(returns: pd.Series, window: int = 20) -> pd.Series:
    """滚动窗口已实现波动率。"""
    return returns.rolling(window).std() * np.sqrt(252)

3.4风险调整收益：谁更会「开同样的车」

两个策略，A 年化 15%、波动 10%，B 年化 25%、波动 30%。谁更好？ 如果只看收益，B 赢；但 B 的波动是 A 的三倍，你为了多赚 10 个点承担了三倍的风险。 风险调整收益指标就是用来回答这个问题的。

夏普比率

Sharpe = (Rp − Rf) / σp (3.4)

每承担一单位波动，获得多少超额收益。它是量化行业最通用的「成绩单」， 也是最被滥用的指标。它有三个致命缺陷：

  1. 它把上涨的波动也当成风险。一个只涨不跌但涨幅不均的策略，夏普会被压低。
  2. 它假设正态分布。如果策略靠卖尾部保险赚钱（平时小赚、偶尔巨亏），夏普会高得离谱，直到爆仓那天。
  3. 它可以被操纵。把流动性差的资产按模型估值而不是市价，收益序列会变得平滑，夏普虚高。这就是为什么有些基金「夏普 3」，赎回时却拿不到钱。

索提诺比率

Sortino = (Rp − Rtarget) / σ下行 (3.5)

只惩罚下行波动。对于收益分布右偏的策略（趋势跟踪、期权买方），索提诺比夏普更公平。

卡玛比率

Calmar = CAGR / |MaxDD| (3.6)

每承受 1% 的最大回撤，换来多少年化收益。这是最贴近「投资者体感」的指标—— 因为回撤是你真实会痛的东西。卡玛大于 1 已经算不错，大于 2 属于优秀。

信息比率

IR = α / σ(α) (3.7)

相对于基准的超额收益，除以超额收益的波动。它衡量的是「主动管理能力」的稳定性。 量化基金内部常用它来评价一个策略相对于其风险模型的表现。

指标衡量什么什么时候会骗你
夏普单位总波动的超额收益厚尾、平滑估值、上涨波动大的策略
索提诺单位下行波动的超额收益样本期没有大跌时，下行波动被低估
卡玛收益 / 最大回撤回撤只取了一个点，样本短时不稳定
IR超额收益的稳定性基准选择不当会扭曲结论
胜率盈利交易占比完全忽略盈亏比，单独看毫无意义

3.5回撤：唯一真正会让你出局的指标

最大回撤（Maximum Drawdown）是从历史最高点到之后最低点的跌幅：

MDD = maxt [ (peakt − trought) / peakt ] (3.8)

但最大回撤只是故事的一部分。同样重要的还有两个数字： 回撤持续了多久（underwater duration），以及多久才创新高（recovery time）。 一个 −20% 但三个月就恢复的回撤，和一个 −15% 但持续三年的回撤，对投资者的心理折磨完全不同。

关于回撤，有一个经验关系值得记住：回撤越深，回本需要的涨幅越夸张。 亏 10% 要涨 11.1%，亏 30% 要涨 42.9%，亏 50% 要涨 100%，亏 80% 要涨 400%。 这就是为什么风险管理的首要目标不是「多赚」，而是「别亏大」。

回撤的心理阈值

研究表明，大多数投资者在回撤 20%–25% 时开始出现非理性行为（赎回、砍仓、加杠杆赌回来）。 这意味着：如果你的策略历史最大回撤是 30%，你大概率拿不住它。 选择策略时，要选「回撤在你心理承受范围内」的那个，而不是收益最高的那个。

3.6分布的形状：偏度与峰度

正态分布由均值 and 方差两个参数完全决定。但真实收益分布有第三个和第四个特征：

  • 偏度（skewness）：分布不对称的程度。负偏 = 左尾长 = 偶尔巨亏。卖期权、做空波动率的策略都是负偏。
  • 峰度（kurtosis）：尾部的厚度。超额峰度 > 0 表示极端值比正态分布更频繁。股票日收益的超额峰度通常在 3–10 之间。

这两个数字之所以重要，是因为它们决定了「平均」是否可信。 一个负偏、高峰度的策略，可能连续 300 天每天赚 0.05%，然后在第 301 天亏掉 40%。 它的夏普比率会非常漂亮，因为夏普完全看不见那个 −40%。

一个判断练习

看到一条几乎笔直向上的资金曲线，先别羡慕。问三个问题： ① 它的收益是不是集中在少数几天？② 它有没有在极端行情里交易过？③ 它的估值是市价还是模型价？ 三个问题里有一个答不上来，这条曲线就不可信。

3.7相关性：分散的数学

两个资产的组合波动率不是各自波动率的平均，而是：

σp² = w₁²σ₁² + w₂²σ₂² + 2w₁w₂ρσ₁σ₂ (3.9)

当 ρ = 1，波动率线性相加，分散无效；当 ρ = 0，波动率按平方和开根号， 两个同波动率的资产各占一半，组合波动率降到原来的 70.7%；当 ρ = −1，理论上可以完全消除波动。

但这里有一个残酷的现实：相关性在危机时会趋近于 1。 平时不相关的资产，在流动性危机里会一起被抛售，因为它们变成了同一个东西——「需要卖掉的资产」。 2008 年、2020 年 3 月、2022 年，都上演过这一幕。

实践含义

用长期平均相关性做风险模型，会系统性低估尾部风险。 稳健的做法是：同时看「正常时期相关性」和「压力时期相关性」， 并在仓位设计里假设后者才是真的。这也是第九章压力测试的起点。

3.9动手：一个够用的指标库

这段代码值得存下来，后面每一章都会用到。它刻意写得很直白，方便你改。

metrics.py
import numpy as np
import pandas as pd


def to_returns(equity: pd.Series) -> pd.Series:
    return equity.pct_change().dropna()


def cagr(equity: pd.Series, periods_per_year: int = 252) -> float:
    """复合年化增长率。用首尾净值计算，不受中间波动干扰。"""
    n = len(equity) / periods_per_year
    if n <= 0 or equity.iloc[0] <= 0:
        return np.nan
    return (equity.iloc[-1] / equity.iloc[0]) ** (1 / n) - 1


def ann_vol(returns: pd.Series, periods_per_year: int = 252) -> float:
    return returns.std() * np.sqrt(periods_per_year)


def sharpe(returns: pd.Series, rf: float = 0.0, periods_per_year: int = 252) -> float:
    excess = returns - rf / periods_per_year
    sd = excess.std()
    return np.nan if sd == 0 else excess.mean() / sd * np.sqrt(periods_per_year)


def sortino(returns: pd.Series, rf: float = 0.0, periods_per_year: int = 252) -> float:
    excess = returns - rf / periods_per_year
    downside = excess[excess < 0].std()
    return np.nan if downside == 0 else excess.mean() / downside * np.sqrt(periods_per_year)


def drawdown_series(equity: pd.Series) -> pd.Series:
    """水下曲线：当前净值相对历史最高点的跌幅（负数）。"""
    peak = equity.cummax()
    return equity / peak - 1


def max_drawdown(equity: pd.Series) -> float:
    return drawdown_series(equity).min()


def drawdown_stats(equity: pd.Series) -> dict:
    """最大回撤 + 最长水下时间（交易日）。"""
    dd = drawdown_series(equity)
    mdd = dd.min()
    trough = dd.idxmin()
    peak = equity.loc[:trough].idxmax()
    recovery = equity.loc[trough:][equity.loc[trough:] >= equity.loc[peak]]

    longest, current = 0, 0
    for v in dd:
        current = current + 1 if v < 0 else 0
        longest = max(longest, current)

    return {
        "max_drawdown": mdd,
        "peak": peak,
        "trough": trough,
        "recovery": recovery.index[0] if len(recovery) else None,
        "underwater_days": longest,
    }


def summary(equity: pd.Series) -> pd.Series:
    r = to_returns(equity)
    dd = drawdown_stats(equity)
    return pd.Series({
        "CAGR": cagr(equity),
        "Vol": ann_vol(r),
        "Sharpe": sharpe(r),
        "Sortino": sortino(r),
        "MaxDD": dd["max_drawdown"],
        "Calmar": cagr(equity) / abs(dd["max_drawdown"]) if dd["max_drawdown"] else np.nan,
        "UnderwaterDays": dd["underwater_days"],
    })

一个实现细节

drawdown_stats 里查找 recovery 的写法用了布尔索引，在长序列上会慢。 生产环境建议用 np.argmax 找到第一个 True 的位置，或者直接用累计最大值做向量化。 这类「能跑但不够快」的代码，在回测里会被调用几十万次，值得优化。

3.10本章陷阱清单

  • 用算术平均汇报收益，把 17.5% 说成「年化」。
  • 只看夏普，不看偏度和回撤。
  • 用日波动率 × √252 去估计包含极端行情的年度风险。
  • 把「最大回撤」当成「未来最大回撤」。历史极值只是下限，不是上限。
  • 在样本期没有危机的情况下，相信「低相关性」能保护你。
  • 忽略回撤持续时间——它比深度更能摧毁投资者的执行力。

数据
量化的原材料

一个策略的成败，在写第一行模型代码之前就决定了一半——由你手里的数据决定。 复权算错、幸存者偏差、财报用了未来信息、停牌股票被当成可交易， 这些错误不会让回测报错，只会让它变得特别好看。这一章教你审计自己的数据。

阅读 34 分钟 难度 中级 代码 数据审计

在软件工程里，垃圾进、垃圾出是一个老笑话。但在量化里，它更狠： 垃圾数据进来，出来的不是垃圾，而是一条漂亮的、会让你押上真金白银的资金曲线。 因为回测框架不会质疑数据，它只会忠实地把你的错误放大成收益。

我见过最常见的新手翻车现场，不是模型太复杂，而是：用今天的沪深 300 成分股， 回测了 2015 年的行情。那十年里被剔除的、退市的、暴雷的公司，全部从样本里消失了， 剩下的自然都是赢家。这个策略的年化收益能凭空多出 5 到 10 个百分点，而代码一行都没错。

4.2K 线是怎么来的，以及它的三个坑

一根日 K 线包含四个价格和一个成交量。它们不是在同一时刻产生的：

  • 开盘价：集合竞价的成交价（A 股 9:25）。
  • 最高 / 最低：盘中任意时刻的极值，你不知道先后顺序。
  • 收盘价：收盘集合竞价的成交价（A 股 14:57–15:00）。
  • 成交量：全天累计，包含集合竞价。
坑一：你不知道高低点谁先出现

如果一根 K 线最高 10.5、最低 9.8，你的策略规则是「先触及 10.5 买入，再跌破 9.8 止损」， 回测引擎必须猜一个顺序。猜错了，结果天差地别。这就是为什么日内的止盈止损规则， 不能用日 K 线回测——你需要分钟线或逐笔数据。

坑二：收盘价不是可成交价

收盘价是集合竞价的结果，你在盘中任何时刻都无法以它成交。用「当日收盘价」作为买入价， 等于假设你有预知能力，在 14:59:59 精确下单并成交。这是最普遍的前视偏差。 正确做法：信号用 T 日收盘计算，成交用 T+1 日开盘（或 VWAP）。

坑三：成交量包含了你无法参与的部分

集合竞价的成交量、大宗交易的量、以及算法单的冰山委托，都会让「成交量」这个数字 高估你可获得的流动性。经验法则是：你的单笔订单不超过该周期成交量的 1%–5%， 超过就会显著冲击价格。

4.3复权：一个必须算对的减法

股票会分红、送股、拆股。如果不做调整，价格序列会在除权日出现一个巨大的跳空， 而那个跳空不是收益，是会计处理。

假设某股票前收盘 100 元，每 10 股送 10 股（相当于 1 拆 2），除权后理论开盘价是 50 元。 如果你直接用原始价格算收益，会得到 −50% 的假暴跌。

方式调整基准特点适用
前复权以最新价为基准，向前调整历史价最新价 = 真实价；历史价会随时间变化看图、技术分析
后复权以上市首日为基准，向后调整历史价不变，最新价被放大回测计算收益
不复权原始成交价有跳空，但价格是真实的撮合、订单价格、涨跌停判断
实践原则

算收益用后复权，下单价用不复权。 这两件事经常被混在一起。回测里如果全程用后复权价去挂单，你会挂在一个现实中不存在的价格上； 如果全程用不复权价算收益，你会在每个除权日凭空亏掉一笔。 正确做法：维护两套价格序列，或者在成交时用「复权因子」做转换。

4.4幸存者偏差：死人不会说话

这是回测里最隐蔽、杀伤力最大的偏差。它的本质是：你今天的股票池，是「活到今天」的股票。 而那些退市的、被并购的、财务造假被摘牌的，全部不在里面。

后果有多严重？学术研究显示，用「当前成分股」回测美股 1980–2010 的策略， 年化收益会被高估 1.5%–4%。在 A 股，由于退市率较低但借壳、重组频繁，偏差的形式不同但同样存在。

4.5前视偏差：用了未来的信息

前视偏差（look-ahead bias）是指：在决策时，使用了当时还不可能知道的信息。 它有很多变体，每一种都很常见。

变体一：财报的「报告期」与「公布日」

2024 年年报的数据，报告期是 2024-12-31，但公布日可能是 2025-04-28。 如果你在 2025-01-15 就用上了这份年报，你提前了三个半月知道未来。

可用日期 = max(报告期, 实际公布日) + 1 个交易日 (4.1)

严谨的做法是使用 Point-in-Time（PIT）数据：每个财务字段都带有「何时可用」的时间戳。 没有 PIT 数据时，一个保守的近似是：年报用次年 5 月 1 日，一季报用 5 月 1 日， 半年报用 9 月 1 日，三季报用 11 月 1 日。

变体二：用全样本做标准化

变体四：参数的全局最优

这是最隐蔽的一种：你在全样本上找到了最优参数，然后报告全样本的回测结果。 这等于用未来数据选择了参数。第八章会讲怎么用 walk-forward 解决它。

一个自检方法

把你的策略在「随机打乱日期标签」的数据上跑一遍。如果它还能赚钱， 说明你的流程里有前视偏差或数据泄漏。这是最快的泄漏检测器。

import pandas as pd
import numpy as np


def audit_prices(df: pd.DataFrame) -> pd.DataFrame:
    """df 需包含: date, symbol, open, high, low, close, volume"""
    df = df.sort_values(["symbol", "date"])
    g = df.groupby("symbol", group_keys=False)

    report = pd.DataFrame({
        "rows": g.size(),
        "missing_close": g["close"].apply(lambda s: s.isna().sum()),
        "zero_volume_days": g["volume"].apply(lambda s: (s == 0).sum()),
        "dup_dates": g["date"].apply(lambda s: s.duplicated().sum()),
        "max_abs_ret": g["close"].apply(
            lambda s: s.pct_change().abs().max()
        ),
    })

    # 价格逻辑校验：high 必须 >= max(open, close)，low <= min(open, close)
    bad_ohlc = ((df["high"] < df[["open", "close"]].max(axis=1)) |
                (df["low"] > df[["open", "close"]].min(axis=1))).sum()
    print(f"OHLC 逻辑错误: {bad_ohlc} 行")

    # 单日涨跌幅超过 50%（A 股非 ST 不可能）标记为可疑
    report["suspicious"] = report["max_abs_ret"] > 0.5
    return report.sort_values("suspicious", ascending=False)

4.7数据源：怎么选，怎么验

不要迷信「免费数据」。免费数据的问题不是不准，而是你不知道它哪里不准。 选数据源时，看四个维度：

  1. 覆盖范围：是否包含退市股票？是否有历史成分股？
  2. 时间戳：是否提供 PIT？财报有没有公布日字段？
  3. 调整方式：复权因子是否单独提供？分红送股是否完整？
  4. 可复现性：数据会不会被静默修订？有没有版本快照？
交叉验证

任何关键数据，至少用两个来源对一遍。具体做法：随机抽 20 个「股票 × 日期」， 手工到交易所网站或行情软件核对收盘价与成交量。听起来很土，但这是唯一能建立信任的方法。 我见过太多人花了三个月调模型，最后发现是数据源把「手」当成「股」。

4.8本章陷阱清单

  • 用当前成分股回测历史（幸存者偏差）。
  • 用报告期代替公布日（前视偏差）。
  • 用全样本均值/标准差做标准化（数据泄漏）。
  • 用收盘价作为成交价。
  • 用不复权价计算收益，或用复权价挂单。
  • 把停牌日的前向填充价格当成真实成交价。
  • 不检查 OHLC 的逻辑关系（high < close 之类的脏数据）。
  • 相信「免费数据」而不做交叉验证。

金融市场是一台专门生产「假规律」的机器。随机波动会长得像趋势， 噪声会长得像信号，而你恰好会在看到它的那一刻相信它。 这一章给你三件武器：样本量的直觉、假设检验的正确用法、以及对付多重检验的纪律。

先做一个思想实验。让 1000 个人各自抛 10 次硬币，总会有几个人连续抛出 10 个正面。 如果你只采访这几个人，你会得出「有人天生擅长抛正面」的结论，还会想拜他为师。 金融市场每天都在生产这样的人——他们叫「去年的冠军基金」。

统计学的全部意义，就是让你在这种情况下保持清醒。它不告诉你「什么是对的」， 它告诉你「这个结果有多可能只是运气」。

5.1大数定律，和小数定律

大数定律说：样本量足够大时，样本均值会收敛到真实期望。 它的潜台词是：「足够大」比你想的大得多。

假设一个策略真实胜率 52%，你想通过观察来确认它大于 50%。需要多少笔交易？ 用标准误公式 SE = √(p(1−p)/n)，要让 2% 的优势达到 2 倍标准误：

n ≈ p(1−p) / (0.01)² ≈ 0.25 / 0.0001 = 2,500 笔 (5.1)

2500 笔。如果你的策略每天交易一次，需要十年。这就是为什么「三个月实盘验证」毫无意义—— 它连噪声都还没走完一个周期。

更麻烦的是，人对随机性的直觉是反的。我们会在 20 次里看到 14 次盈利，就认为「找到了规律」， 这叫小数定律：错误地认为小样本也应该反映总体特征。 赌徒谬误、热手效应、以及大部分技术指标的诞生，都源于这个错误。

一个粗糙但好用的估算

评价一个日频策略，至少需要 3–5 年的日频数据（约 750–1250 个观测）， 才能让夏普比率的标准误降到可接受的范围。少于这个量，你看到的差异大部分是噪声。 公式：SE(Sharpe) ≈ √((1 + SR²/2) / T)，T 为年数。

5.2假设检验：p 值到底在说什么

假设检验的逻辑是反证法：先假设「没有效果」（原假设 H₀），然后看观测到的数据 在这个假设下有多不可能。如果太不可能，就拒绝 H₀。

t = (x̄ − μ₀) / (s / √n) (5.2)

p 值的定义是：在原假设为真的前提下，观测到当前结果或更极端结果的概率。 注意它不是「原假设为真的概率」，也不是「策略有效的概率」。 这个区别被误解了一百年，包括很多博士。

p < 0.05 不意味着什么

它不意味着策略有效，不意味着可复现，不意味着经济意义显著。 它只意味着：如果真实收益是 0，你观测到这么高收益的概率小于 5%。 而在你试了 100 个策略之后，出现至少一个 p < 0.05 的概率是 99.4%。

5.3多重检验：量化研究最大的陷阱

这是本章最重要的一节。假设你完全不懂交易，只是随机生成 1000 个策略， 每个策略都在同一段历史上回测。因为随机性，其中必然有一些看起来非常棒。 如果你挑出最好的那个，你会得到一条年化 30%、夏普 2 的曲线——而它背后的真实 alpha 是零。

5.4Bootstrap：不假设分布的置信区间

传统 t 检验假设收益服从正态分布。但我们已经知道它有厚尾。 Bootstrap 提供了一种不依赖分布假设的方法：有放回地重采样。

做法极其简单：从你的 N 个日收益里，随机抽 N 个（允许重复），算一次夏普； 重复 1000 次，得到夏普的分布；取 2.5% 和 97.5% 分位数，就是 95% 置信区间。

bootstrap.py
import numpy as np

def bootstrap_ci(x, stat, n_boot=2000, alpha=0.05, seed=0):
    """对任意统计量做 bootstrap 置信区间。"""
    rng = np.random.default_rng(seed)
    x = np.asarray(x)
    n = len(x)
    stats = np.empty(n_boot)
    for i in range(n_boot):
        idx = rng.integers(0, n, n)
        stats[i] = stat(x[idx])
    lo, hi = np.quantile(stats, [alpha / 2, 1 - alpha / 2])
    return stat(x), lo, hi


def sharpe(x):
    sd = x.std(ddof=1)
    return np.nan if sd == 0 else x.mean() / sd * np.sqrt(252)

如果你的置信区间是 [−0.3, 2.1]，那么「策略有效」这个结论 就非常脆弱——它和「没有效果」在统计上无法区分。很多研究报告只给点估计， 不给区间，这等于隐藏了不确定性。

Block Bootstrap

普通 bootstrap 假设每个观测独立。但收益有自相关（波动聚集、动量）， 独立重采样会破坏这个结构，低估不确定性。解决办法是按块重采样： 每次抽取连续的一段（比如 20 天），而不是单日。

block_bootstrap.py
def block_bootstrap_ci(x, stat, block=20, n_boot=2000, alpha=0.05, seed=0):
    rng = np.random.default_rng(seed)
    x = np.asarray(x)
    n = len(x)
    n_blocks = int(np.ceil(n / block))
    out = np.empty(n_boot)
    for i in range(n_boot):
        starts = rng.integers(0, n - block, n_blocks)
        sample = np.concatenate([x[s:s + block] for s in starts])[:n]
        out[i] = stat(sample)
    return stat(x), *np.quantile(out, [alpha / 2, 1 - alpha / 2])

5.5置换检验：最诚实的「这会不会是运气」

如果你想知道「我的择时能力是真的，还是运气」，最直接的办法是： 把信号和收益的对应关系随机打乱，看会发生什么。

具体做法：保持收益序列不变，随机重排信号（或日期），重跑策略 1000 次， 得到「无预测能力」情况下的收益分布。如果你的真实收益落在这个分布的 99% 分位之外， 才有资格说「这可能不是运气」。

permutation.py
import numpy as np

def permutation_test(signal, forward_ret, n_perm=2000, seed=0):
    """检验信号与未来收益的关系是否显著。
    signal: 每日信号（-1 ~ 1）
    forward_ret: 次日收益
    """
    rng = np.random.default_rng(seed)
    signal = np.asarray(signal)
    forward_ret = np.asarray(forward_ret)

    real = np.corrcoef(signal, forward_ret)[0, 1]
    null = np.empty(n_perm)
    for i in range(n_perm):
        null[i] = np.corrcoef(rng.permutation(signal), forward_ret)[0, 1]

    p = (np.sum(np.abs(null) >= abs(real)) + 1) / (n_perm + 1)
    return real, p, null

这个检验的妙处在于：它不假设任何分布，直接回答「在完全没有预测能力的世界里， 我看到的这个相关性有多常见」。它比 t 检验更稳健，也更难被自欺欺人。

5.6平稳性：金融时间序列的麻烦

大部分统计方法都假设数据是平稳的：均值和方差不随时间变化。 但价格显然不平稳（长期上涨），波动率也不平稳（聚集），连相关性都不平稳（危机时一起跌）。

实践中的处理方式：

  • 用收益率，不用价格。收益率比价格更接近平稳。
  • 用滚动窗口或扩展窗口。承认参数会变，定期重估。
  • 做差分。如果序列有单位根，差分后再建模。
  • 不要外推太远。任何模型的预测能力都随时间衰减。
一个实用检验

ADF 检验（Augmented Dickey-Fuller）用来判断序列是否有单位根。 在 Python 里用 statsmodels.tsa.stattools.adfuller。 但要注意：通过了 ADF 检验不等于平稳，只说明「没有单位根」。 结构突变（比如 2020 年 3 月）会让所有历史检验失效。

5.7回归：几何直觉与 R² 的欺骗性

线性回归在几何上就是把 y 投影到 X 张成的空间上。 残差是投影的垂线，所以残差和 X 正交。这个视角比公式更有用： 它告诉你 OLS 找到的是「在 X 能解释的方向上，最接近 y 的那个点」。

β̂ = (XᵀX)−1Xᵀy     R² = 1 − SSres/SStot (5.3)

R² 表示「y 的方差中被 X 解释的比例」。它在量化里经常被误读：

  • R² = 0.02 在预测股票收益时可能已经很有价值（因为信噪比极低）。
  • R² 高不代表因果，也不代表能赚钱（可能只是同期相关）。
  • 加入更多变量，R² 一定上升，哪怕变量是噪声。所以要看调整 R² 或样本外 R²。
伪回归

两个都有趋势的时间序列做回归，会得到极高的 R² 和显著的 t 值， 但两者可能毫无关系（比如「中国 GDP」和「美国人口」）。 这叫伪回归（spurious regression）。解决办法：差分、加协整检验、或者用收益率而非价格。

5.8本章陷阱清单

  • 用 3 个月的数据判断策略有效。
  • 把 p < 0.05 当成「策略有效」。
  • 试了 50 个变体，只报告最好的那个。
  • 用普通 bootstrap 处理有自相关的收益序列。
  • 对价格做回归而不做差分。
  • 用 R² 高低判断因子好坏。
  • 忽略样本外检验，或者样本外只留了最后 10%。

本章练习

  1. 用 bootstrap_ci 计算一个真实策略夏普的 95% 置信区间。它跨过 0 了吗？
  2. 生成 500 个纯随机策略（零 alpha），记录最大夏普。改变回测年数，观察最大夏普如何变化，验证 √(2 ln N / T) 这个近似。
  3. 对一个你相信的因子做置换检验，看 p 值是多少。
  4. 构造两个有趋势但无关的序列，做回归，观察 R² 有多高。然后差分后再回归。

本章要点

  • 确认 2% 的胜率优势需要约 2500 笔交易；短期实盘验证没有统计意义。
  • p 值是「H₀ 为真时观测到该结果的概率」，不是「策略有效的概率」。
  • 多重检验必然产生假冠军；记录试验次数，使用 Deflated Sharpe 或 FDR。
  • Bootstrap 给出不依赖分布假设的置信区间；有自相关时用 Block Bootstrap。
  • 置换检验直接回答「这会不会是运气」，是最诚实的检验之一。
  • 金融序列不平稳；用收益率、滚动窗口、差分来逼近平稳。

Alpha 与因子
把收益拆开看

你赚的钱，可能只是因为你承担了市场风险——那不叫本事，叫 beta。 真正的 alpha 是扣除所有已知风险暴露之后，还剩下的那部分。 这一章教你用因子模型把收益拆开，用 IC 衡量预测力，并避开「因子动物园」的陷阱。

2013 年，一位对冲基金经理在电视上说：「我们的策略跟市场无关，我们靠选股。」 主持人问：「那 2008 年你们为什么跌了 40%？」他沉默了三秒。 那三秒里发生的事，就是 beta 伪装成 alpha 被当场拆穿。

这一章的核心任务只有一个：给你一把刀，把「运气」「市场」「风格」「真本事」切开。 切不开这四样东西，你永远不知道自己为什么赚钱，也就永远不知道什么时候会开始亏。

6.1Alpha 的定义：回归的残差

最干净的定义来自回归。把你的策略收益 Rp 对一组风险因子 F 做回归：

Rp − Rf = α + β₁F₁ + β₂F₂ + … + βkFk + ε (6.1)

这里的 α 就是 alpha：无法被这些因子解释的平均收益。 如果 α 显著大于 0，说明你有这些因子之外的能力；如果 α ≈ 0 而 R² 很高， 说明你只是在重复承担已知风险，赚的是 beta 的钱。

一句话记住

Beta 是「你坐在哪条船上」，Alpha 是「你在船上做了什么」。 牛市里所有人都是股神，因为船在涨。只有扣除船的速度，才能看出谁在划桨。

6.2CAPM：只有一个因子的世界

CAPM 是最简单的因子模型：只有一个因子——市场。

E(Ri) − Rf = βi [E(Rm) − Rf] (6.2)

β 衡量个股对市场波动的敏感度。β = 1.2 意味着市场涨 1%，它平均涨 1.2%。 用回归估计：β = Cov(Ri, Rm) / Var(Rm)。

CAPM 在实证上表现很差——它解释了收益的横截面差异不到 1%。 但它的思想极其重要：任何超额收益都必须相对于某个风险基准来定义。 没有基准的「跑赢」是没有意义的。

基准选择会改变结论

一个只买科技股的策略，用沪深 300 做基准会显示巨大的 alpha； 用中证 TMT 指数做基准，alpha 可能归零。这不是数学问题，是诚实问题。 选基准时，要选「和你持仓最像、但不需要你任何技能就能买到」的那个。

6.3多因子模型：把风格剥离出来

Fama-French 在 CAPM 上加了两个因子：规模（SMB）和价值（HML）。 后来 Carhart 加了动量（MOM），Fama-French 又加了盈利（RMW）和投资（CMA）。

因子全称构造经济解释
MKT市场市场组合 − 无风险利率承担系统性风险
SMB规模小市值 − 大市值小公司流动性差、风险高
HML价值高 B/P − 低 B/P困境公司需要风险补偿
MOM动量过去 12 月赢家 − 输家反应不足、资金流持续

这六个因子能解释股票收益横截面的大部分差异。实践含义是： 你的策略如果暴露在 SMB 或 MOM 上，那部分收益不能算 alpha。 很多「小盘成长」基金的超额收益，扣除风格后接近于零。

6.4因子怎么造：排序、分组、多空

一个因子本质上是一个打分函数：给每只股票一个数字，然后按数字排序。 标准流程如下：

  1. 定义原始指标：比如账面市值比 B/P。
  2. 清洗：剔除负值、极值、缺失。
  3. 标准化：横截面 z-score 或排序。
  4. 中性化：剔除行业、市值的影响（否则你测的是行业或规模）。
  5. 分组：按分位数分成 5 组或 10 组。
  6. 构建组合：等权或市值加权，做多最高组、做空最低组。
  7. 评估：看多空收益、单调性、IC、换手。
分组数量的取舍

分 5 组，每组样本多、噪声小，但区分度低；分 10 组，区分度高，但极端组容易受个别股票影响。 学术研究常用 10 组，实盘常用 5 组或直接用连续打分。个人建议：先用 5 组看单调性， 再用 10 组看极端收益。

6.5IC：因子预测力的相关系数

IC（Information Coefficient）是每个横截面上，因子值与未来收益的相关系数。 它是因子研究里最常用的单一指标。

ICt = corr( factori,t , returni,t+1 )   （横截面） (6.3)

几个经验基准：

指标含义经验阈值
IC 均值预测力的方向与强度|均值| > 0.03 已可用，> 0.06 很好
ICIRIC 均值 / IC 标准差> 0.3 可用，> 0.5 优秀
IC 胜率IC > 0 的期数占比> 55% 说明稳定
RankIC用秩相关代替线性相关对异常值更稳健，通常更可信
IC 高不等于能赚钱

IC 衡量的是「排序能力」，不是「收益能力」。一个 IC = 0.05 的因子， 如果只在对冲成本很高的股票上有效，扣掉交易成本后可能亏钱。 更重要的检验永远是：扣成本后的多空收益。

6.6风格因子地图

所有因子最终都能归入几个大类。理解这张地图，你就不会把同一个东西换个名字当成新发现。

价值 Value

B/P、E/P、EV/EBITDA、股息率。逻辑：便宜的东西长期跑赢。失效期：2010s 成长股泡沫、价值陷阱。

动量 Momentum

过去 3–12 月收益。逻辑：反应不足与资金流。失效期：剧烈反转（2009、2020 年 3 月）。

质量 Quality

ROE、毛利率、低负债、盈利稳定性。逻辑：好公司被低估。与价值常负相关。

低波 Low Vol

过去波动率、beta。逻辑：投资者偏好彩票型股票，低波被低估。杠杆约束下的必然结果。

规模 Size

市值。逻辑：小公司风险溢价。但 1980 年后在美股大幅衰减，A 股仍有争议。

流动性 Liquidity

换手率、Amihud 非流动性。逻辑：流动性差的资产需要补偿。与规模高度相关。

这六类之间并不独立。小市值股票往往流动性差、波动高；价值股往往质量差。 所以你在测试一个新因子时，必须做正交化：剔除它和已知因子的相关性， 看剩下的部分还有没有预测力。

import numpy as np
import pandas as pd


def neutralize(factor: pd.Series, exposures: pd.DataFrame) -> pd.Series:
    """对因子做横截面回归，返回残差（已剔除 exposure 的影响）。
    factor / exposures 的 index 必须对齐（同一横截面）。
    """
    y = factor.values
    X = np.column_stack([np.ones(len(exposures)), exposures.values])
    mask = np.isfinite(y) & np.isfinite(X).all(axis=1)
    resid = np.full_like(y, np.nan, dtype=float)
    beta, *_ = np.linalg.lstsq(X[mask], y[mask], rcond=None)
    resid[mask] = y[mask] - X[mask] @ beta
    return pd.Series(resid, index=factor.index)


# 行业中性化：先做行业哑变量，再回归
def industry_neutralize(factor: pd.Series, industry: pd.Series) -> pd.Series:
    dummies = pd.get_dummies(industry, drop_first=True).astype(float)
    return neutralize(factor, dummies)

6.7因子衰减与换手

一个因子在第 t 期给出的信号，对 t+1 期的收益预测最强，然后逐渐衰减。 衰减速度决定了你的调仓频率，也决定了交易成本。

换手率的估算很简单：每个调仓期，计算组合中权重变化绝对值之和的一半。 年化换手 500% 意味着你每年把整个组合换了 5 遍。按单边 10bps 成本算， 年成本约 10%。这个数字必须从你的毛收益里扣掉。

factor_test.py
import numpy as np
import pandas as pd

def factor_test(panel: pd.DataFrame, factor: str, ret: str,
                n_groups: int = 5, quantile: bool = True) -> dict:
    """panel 需包含: date, symbol, factor, forward_return"""
    rows = []
    for date, g in panel.groupby("date"):
        g = g.dropna(subset=[factor, ret])
        if len(g) < n_groups * 5:
            continue
        # 横截面排序
        if quantile:
            g = g.assign(score=g[factor].rank(pct=True))
        else:
            g = g.assign(score=(g[factor] - g[factor].mean()) / g[factor].std())
        g = g.assign(grp=pd.qcut(g["score"], n_groups, labels=False, duplicates="drop"))

        ic = g["score"].corr(g[ret], method="spearman")
        grp_ret = g.groupby("grp")[ret].mean()
        rows.append({"date": date, "ic": ic,
                     **{f"g{k}": v for k, v in grp_ret.items()}})

    res = pd.DataFrame(rows).set_index("date")
    gcols = [c for c in res.columns if c.startswith("g")]
    res["long_short"] = res[gcols[-1]] - res[gcols[0]]

    return {
        "ic_mean": res["ic"].mean(),
        "ic_std": res["ic"].std(),
        "icir": res["ic"].mean() / res["ic"].std(),
        "ic_winrate": (res["ic"] > 0).mean(),
        "ls_mean": res["long_short"].mean(),
        "ls_sharpe": res["long_short"].mean() / res["long_short"].std() * np.sqrt(12),
        "group_returns": res[gcols].mean(),
        "series": res,
    }

6.10陷阱：因子动物园

学术界已经发表了 400 多个「显著」的因子。其中大部分是数据挖掘的产物。 2016 年，Harvey、Liu 和 Zhu 发表了一篇著名论文，指出考虑到多重检验， 新因子的 t 值需要超过 3.0（而不是传统的 2.0）才值得认真对待。

  • 只在论文里有效的因子，通常在你手里也无效——因为发表本身就是一种选择偏差。
  • 因子拥挤：当太多钱涌向同一个因子，它的收益会被压缩，直到某天剧烈反转。
  • 「新因子」往往只是旧因子的非线性变换，先做相关性检验。
  • 因子在不同市场、不同时期的表现差异巨大，别直接照搬美股结论。

策略的四种原型

市面上有成千上万种策略，但剥掉包装之后，它们几乎都落在四个原型里： 趋势、回归、套利、做市。每个原型的收益来源不同、失效条件不同、容量也不同。 理解原型，你就不需要背诵策略，而是能在需要时自己造一个。

新手最喜欢问：「什么策略最赚钱？」这个问题没有答案，因为策略不是菜谱，是对某种市场缺陷的下注。 你要先找到缺陷，再设计策略去收割它。而市场的缺陷，本质上只有四类： 趋势会延续、价格会回归、同一东西在不同地方价格不同、以及有人急着成交。

7.1趋势跟踪：赌「惯性」

收益来源

趋势跟踪假设：涨的东西会继续涨，跌的东西会继续跌。这个假设在有效市场里不该成立， 但现实中它成立，原因有三：

  • 行为偏差：投资者对消息反应不足，然后过度反应，形成延续。
  • 资金流：指数基金、CTA、风险平价基金按规则加仓，形成机械性买盘。
  • 宏观周期：经济扩张与收缩有持续性，商品和利率会走出长趋势。

趋势跟踪的典型画像是：胜率 35%–45%，盈亏比 2–4，最大回撤 20%–30%， 大部分年份小赚小亏，少数年份暴赚。它靠的是「肥尾」——抓住几次大行情。

三种实现

方法规则特点
双均线快线上穿慢线做多，下穿平仓最经典，滞后明显，震荡市反复止损
突破价格突破 N 日高点做多海龟交易法，趋势启动快，假突破多
时序动量过去 12 月收益为正则持有学术验证最充分，换手低，适合多资产

关键细节：止损与仓位

趋势跟踪的收益分布是「多次小亏 + 少数大赚」。这意味着两件事： 止损必须坚决（否则小亏会变成大亏，破坏分布）， 盈利必须让它跑（否则你砍掉了唯一的收益来源）。

import numpy as np
import pandas as pd


def atr(df: pd.DataFrame, n: int = 14) -> pd.Series:
    """平均真实波幅：衡量波动，用于止损距离与仓位。"""
    h, l, c = df["high"], df["low"], df["close"]
    tr = pd.concat([
        h - l,
        (h - c.shift()).abs(),
        (l - c.shift()).abs(),
    ], axis=1).max(axis=1)
    return tr.rolling(n).mean()


def trend_signal(df: pd.DataFrame, fast: int = 20, slow: int = 60) -> pd.DataFrame:
    """双均线 + ATR 跟踪止损。返回信号与止损价。"""
    out = df.copy()
    out["ma_f"] = out["close"].rolling(fast).mean()
    out["ma_s"] = out["close"].rolling(slow).mean()
    out["atr"] = atr(out)

    # 1 = 持多，0 = 空仓
    out["signal"] = (out["ma_f"] > out["ma_s"]).astype(int)

    # 跟踪止损：入场后记录最高价，止损线 = 最高价 - 2.5 ATR
    out["peak"] = out["close"].where(out["signal"] == 1).ffill()
    out["stop"] = out["peak"] - 2.5 * out["atr"]
    out["exit"] = (out["close"] < out["stop"]) & (out["signal"] == 1)

    out.loc[out["exit"], "signal"] = 0
    return out


def backtest_trend(df: pd.DataFrame, risk_per_trade: float = 0.01,
                   capital: float = 1_000_000) -> pd.Series:
    """按 ATR 止损距离计算仓位，逐日盯市。"""
    df = trend_signal(df)
    equity = capital
    pos = 0.0
    curve = []

    for i in range(1, len(df)):
        row, prev = df.iloc[i], df.iloc[i - 1]

        # 信号变化时调整仓位
        if row["signal"] == 1 and pos == 0:
            stop_dist = 2.5 * row["atr"]
            if stop_dist > 0:
                pos = (equity * risk_per_trade) / stop_dist
        elif row["signal"] == 0 and pos > 0:
            equity += pos * (row["open"] - prev["close"])
            pos = 0.0

        if pos > 0:
            equity += pos * (row["close"] - prev["close"])
        curve.append(equity)

    return pd.Series(curve, index=df.index[1:])
趋势跟踪最难受的地方

震荡市。价格在两条均线之间来回穿，你连续止损 8 次，每次亏 1%， 然后开始怀疑策略。第 9 次信号出现时你不敢进，结果那是全年最大的一波行情。 趋势策略的钱，是在你快要放弃的时候赚到的。

7.2均值回归：赌「橡皮筋」

收益来源

价格偏离价值后会回来。偏离的原因可能是流动性冲击、情绪、指数调整、 或者单纯的过度反应。回归策略赚的是「纠偏」的钱。

它的画像是趋势的反面：胜率 60%–75%，盈亏比 0.5–1，最大回撤可能很深。 因为「偶尔一次不回归」，会变成巨额亏损。LTCM 就是这么死的。

def bollinger_signal(df: pd.DataFrame, n: int = 20, k: float = 2.0) -> pd.DataFrame:
    """价格跌破下轨做多，回到中轨平仓；反手做空对称。"""
    out = df.copy()
    out["mid"] = out["close"].rolling(n).mean()
    out["sd"] = out["close"].rolling(n).std()
    out["upper"] = out["mid"] + k * out["sd"]
    out["lower"] = out["mid"] - k * out["sd"]

    out["signal"] = 0
    out.loc[out["close"] < out["lower"], "signal"] = 1     # 超卖做多
    out.loc[out["close"] > out["upper"], "signal"] = -1    # 超买做空

    # 回到中轨即平仓（用 shift 避免同日前视）
    out["exit_long"] = out["close"] >= out["mid"]
    out["exit_short"] = out["close"] <= out["mid"]
    return out

配对交易：更纯粹的回归

单资产回归的问题是你不知道「均值」在哪。配对交易解决了这个问题： 找两个历史上有稳定关系的资产（比如两家同行业公司、ETF 与成分股）， 当它们的价差偏离历史均值时，做多低估的、做空高估的。

关键是协整（cointegration），不是相关。两个都上涨的股票可以高度相关， 但价差可能永远扩大。协整检验的是「价差是否平稳」，这才是可回归的前提。

import numpy as np
import pandas as pd
import statsmodels.api as sm
from statsmodels.tsa.stattools import coint


def find_pairs(prices: pd.DataFrame, pvalue_threshold: float = 0.05):
    """在候选池里找协整对。prices 的列是标的，行是日期。"""
    cols = prices.columns
    results = []
    for i in range(len(cols)):
        for j in range(i + 1, len(cols)):
            a, b = prices[cols[i]], prices[cols[j]]
            score, pvalue, _ = coint(a, b)
            if pvalue < pvalue_threshold:
                # 用 OLS 估计对冲比率
                beta = sm.OLS(a, sm.add_constant(b)).fit().params.iloc[1]
                spread = a - beta * b
                results.append({
                    "a": cols[i], "b": cols[j],
                    "pvalue": pvalue, "beta": beta,
                    "spread_std": spread.std(),
                    "half_life": half_life(spread),
                })
    return pd.DataFrame(results).sort_values("pvalue")


def half_life(spread: pd.Series) -> float:
    """用 AR(1) 估计均值回归的半衰期（天）。"""
    lag = spread.shift(1).dropna()
    delta = spread.diff().dropna()
    beta = sm.OLS(delta, sm.add_constant(lag)).fit().params.iloc[1]
    return -np.log(2) / beta if beta < 0 else np.inf


def pairs_signal(spread: pd.Series, entry_z: float = 2.0, exit_z: float = 0.5):
    """z-score 突破入场，回归到均值附近出场。"""
    z = (spread - spread.rolling(60).mean()) / spread.rolling(60).std()
    pos = pd.Series(0, index=spread.index)
    pos[z > entry_z] = -1      # 价差过高：做空 a、做多 b
    pos[z < -entry_z] = 1      # 价差过低：做多 a、做空 b
    pos[z.abs() < exit_z] = 0  # 回归平仓
    return pos.ffill().fillna(0)
配对交易的真实风险

协整关系会断裂。并购、监管变化、技术替代，都会让两家公司「从此不再是同一个东西」。 回测里它只是一次 3 个标准差的偏离，实盘里它是 −30% 的亏损。 配对交易必须有基本面止损：当价差偏离超过历史极值 1.5 倍时，认输离场。

7.3套利：赚「同一东西的价格差」

套利是最接近「无风险」的策略，也正因如此，它的空间最窄、竞争最激烈。

期现套利

股指期货与现货指数的基差。当期货升水超过持有成本，买现货、卖期货，到期收敛获利。

跨期套利

同一品种不同月份合约的价差。近月与远月的价差偏离正常区间时入场。

ETF 折溢价

ETF 二级市场价格与净值（IOPV）的偏离。折价买入、赎回成分股卖出。

统计套利

不是严格无风险，而是「大概率收敛」。配对交易、指数成分替换都属于这一类。

套利的敌人不是方向判断错误，而是执行失败：腿没成交、被强行平仓、 流动性消失、或者监管改变规则。所以套利策略的核心能力是工程，不是预测。

7.4做市：赚「急」的钱

做市商同时挂买单和卖单，赚买卖价差。他们的对手是「急着成交的人」。 这个生意看起来稳赚，实际上有两个致命风险：

  • 库存风险：你买了很多，价格却一直跌。价差赚了 0.01，库存亏了 0.5。
  • 逆向选择：来跟你成交的人，往往比你知道得更多。你被「选中」了。

做市的数学核心是报价宽度：太窄，被有毒订单流吃掉；太宽，没人跟你成交。 经典的 Glosten-Milgrom 模型和 Avellaneda-Stoikov 模型都在解这个权衡。

最优半价差 ≈ (1/2) · σ · √( 库存风险厌恶 × 剩余时间 ) (7.1)

对个人来说，做市基本不可行——你需要极低的延迟、极低的费率、以及交易所的返佣。 但理解做市，能让你明白为什么你的市价单总是成交在最差的价位。

7.5另外两类：事件与 carry

事件驱动

财报超预期、并购公告、指数成分调整、解禁、回购。事件驱动赚的是 「信息扩散需要时间」的钱。它的难点在于：事件的定义、窗口的选择、以及 你凭什么比别人更快地理解这个事件。

Carry

持有高收益资产、卖出低收益资产，赚取息差。外汇里的套息交易、期货里的期限结构 （backwardation 做多）、债券里的骑乘，都是 carry。它的风险是「平时慢慢赚， 危机时一次性亏光」——典型的负偏策略。

7.7陷阱：把 beta 当成 alpha

这一节值得反复读。大部分「民间高手」的策略，本质上是：

  • 买了一只长期上涨的资产，然后说「我的策略年化 15%」——那是 beta。
  • 在小盘股上做动量，然后说「动量有效」——那是规模 + 动量的混合暴露。
  • 卖出期权收保费，连续 3 年稳定盈利——那是负偏的 carry，风险还没兑现。

检验方法很简单：把你的策略收益对市场、规模、价值、动量做回归。 如果 α 不显著，你赚的就是风格的钱。这不丢人——风格也能赚钱—— 但你必须知道自己在赚什么，否则风格反转时你会毫无准备。

回测
一台诚实的谎言机器

回测的唯一目的是证伪，不是证明。它的价值不在于告诉你「这个策略能赚多少」， 而在于告诉你「在什么条件下它会亏、亏多少、以及我的假设有多脆弱」。 这一章拆解回测里所有的作弊点，并给你一台尽量诚实的引擎。

有一个残酷的统计事实：只要你试的次数够多，任何随机策略都能回测出夏普 2。 回测框架不会阻止你，它会热情地配合你——你调一个参数，它给你一条更漂亮的曲线； 你再调一个，它更好。这个过程有强烈的多巴胺反馈，和打游戏升级一模一样。

所以一个成熟的量化研究者，对回测的态度是敌意的。他不是在问 「怎么让它更好看」，而是在问「我怎么才能证明它是假的」。这一章教你怎么当一个合格的敌人。

8.1回测的完整链条

一个诚实的回测，必须显式地走完这条链。任何一环被跳过，结果就不可信。

8.2向量化 vs 事件驱动

方式做法速度真实性适用
向量化用 pandas/numpy 一次性算完所有日期极快低（难以建模成本与约束）因子研究、快速筛选
事件驱动逐日/逐笔循环，模拟订单生命周期慢 10–100 倍高最终验证、实盘前

正确的工作流是：用向量化做研究，用事件驱动做验证。 向量化帮你快速排除 95% 的坏想法；事件驱动帮你确认剩下的 5% 里， 有多少是被成本杀死的。

向量化最大的坑

df["signal"].shift(1) 看起来解决了前视问题，但如果你在计算 signal 时 用了 df["close"].rolling(20).mean()，这个均值包含了当天收盘价—— 而你在当天收盘时是拿不到「收盘价」的（你要等到收盘那一刻）。 正确做法是 rolling(20).mean().shift(1)，或者明确约定「收盘后计算，次日开盘执行」。

8.3前视偏差的十种变体

我把常见的都列出来，建议做成 checklist，每次回测前过一遍。

  1. 用当日收盘价成交，而信号也用了当日收盘价。
  2. 用未来数据做标准化（全样本均值/方差）。
  3. 财报用报告期而非公布日。
  4. 用当前成分股回测历史。
  5. 用「今天是否 ST/退市」过滤历史样本。
  6. 参数在全样本上优化，然后报告全样本结果。
  7. 用未来的行业分类（公司后来改行了）。
  8. 用调整后的复权价挂单（价格现实中不存在）。
  9. 用「最高价/最低价」判断止盈止损顺序（不知道先后）。
  10. 在信号里用了当天收盘后才公布的公告。
最快的检测方法

把价格序列的日期随机打乱，重跑策略。如果还能赚钱，说明你的信号里有泄漏。 另一个方法：把策略的收益和「未来 1 日收益」做相关，如果相关性异常高（> 0.3）， 几乎可以确定有前视。

总成本 = 佣金 + 税费 + 半价差 + 冲击 + 滑点 (8.1)

8.5成交假设：最容易被忽略的一段

「信号说买，回测就按收盘价买到了」——这是回测里最大的谎言。真实的成交需要回答：

  • 什么时候下单？收盘后？次日开盘？开盘后 30 分钟？
  • 用什么价格？开盘价、VWAP、还是限价单排队？
  • 能不能成交？涨停买不到，跌停卖不掉，停牌无法交易。
  • 成交多少？你的量占盘口多大比例？超过 10% 就会显著冲击。

import numpy as np

def can_trade(row, side: str, limit_pct: float = 0.098) -> bool:
    """A 股涨跌停/停牌过滤。row 需含 open/high/low/close/prev_close/volume。"""
    if row["volume"] <= 0:
        return False                                  # 停牌
    ret = row["open"] / row["prev_close"] - 1
    if side == "buy" and ret >= limit_pct and row["high"] == row["low"]:
        return False                                  # 一字涨停，买不到
    if side == "sell" and ret <= -limit_pct and row["high"] == row["low"]:
        return False                                  # 一字跌停，卖不掉
    return True


def fill_price(open_price: float, side: str, spread_bps: float,
               impact_bps: float, slippage_bps: float) -> float:
    """在开盘价基础上，买方上浮、卖方下调。"""
    total = (spread_bps / 2 + impact_bps + slippage_bps) / 1e4
    return open_price * (1 + total) if side == "buy" else open_price * (1 - total)


def impact_bps(order_value: float, adv_value: float, coef: float = 10.0) -> float:
    """平方根冲击模型：成本 ∝ sqrt(订单占日均成交额比例)。"""
    if adv_value <= 0:
        return 999
    participation = order_value / adv_value
    return coef * np.sqrt(participation) * 100   # 转成 bps

8.6过拟合的数学：为什么「最优参数」是陷阱

假设你有 10 个参数，每个试 5 个值，组合空间是 5¹⁰ ≈ 976 万。 你不需要真的试完——遗传算法、网格搜索、甚至手动调参，都会把你推向 「在这段历史上最好」的那个点。而这个点，大概率是噪声的局部极值。

更 formal 地说：如果 N 个策略的真实夏普都是 0，那么最大夏普的期望约为 √(2 ln N) / √T（T 为年数）。试 100 个、5 年数据， 期望最大夏普约 1.36。这就是为什么「我试了 100 个策略，最好的夏普 1.5」 完全不能说明任何问题。

参数敏感性的正确用法

不要找「最优点」，要找「稳定的高原」。把参数网格画成热力图， 如果最优点周围一片绿（好），说明稳健；如果最优点是孤立的红点，周围全是蓝（差）， 那它是过拟合。宁可要一个平庸但稳定的参数，也不要一个优秀但脆弱的参数。

8.7样本外：Walk-Forward 与 Purged CV

Walk-Forward

把时间切成若干段：用前 3 年训练/选参，第 4 年测试；然后窗口向前滚动一年， 重复。最终把所有测试段拼起来，得到「样本外」的资金曲线。

Purged K-Fold 与 Embargo

如果策略的标签是「未来 20 日收益」，那么相邻样本的标签会重叠。 随机切分会让训练集和测试集共享同一段未来——这叫标签泄漏。

López de Prado 提出的解法是：在训练集和测试集之间挖掉一段 （purge），并额外留出一段缓冲（embargo），确保没有重叠。

purged_cv.py
import numpy as np

def purged_splits(n_samples: int, n_splits: int = 5,
                  label_horizon: int = 20, embargo: int = 5):
    """返回 (train_idx, test_idx)，训练集已剔除与测试集标签重叠的部分。"""
    indices = np.arange(n_samples)
    fold_size = n_samples // n_splits

    for k in range(n_splits):
        test_start = k * fold_size
        test_end = min((k + 1) * fold_size, n_samples)
        test_idx = indices[test_start:test_end]

        # 测试集标签会用到 test_end + horizon 的数据
        purge_end = min(test_end + label_horizon + embargo, n_samples)
        train_idx = np.concatenate([
            indices[:max(0, test_start - label_horizon)],
            indices[purge_end:],
        ])
        if len(train_idx) == 0:
            continue
        yield train_idx, test_idx

8.8动手：一台尽量诚实的回测器

下面这个引擎只有 100 多行，但它把该有的都做了：次日开盘成交、显式成本、 涨跌停过滤、逐日盯市。它的目标不是快，是让你无法自欺。

engine.py
from dataclasses import dataclass
import numpy as np
import pandas as pd


@dataclass
class Costs:
    commission: float = 0.0003     # 双边佣金
    stamp_tax: float = 0.0005      # 卖出印花税
    slippage: float = 0.0010       # 单边滑点（含半价差）


class Backtest:
    """极简事件驱动回测器。

    prices:  MultiIndex (date, symbol) 的 DataFrame，含 open/high/low/close/volume
    target:  MultiIndex (date, symbol) 的目标权重，date 为信号日（收盘后生成）
    """

    def __init__(self, prices: pd.DataFrame, target: pd.DataFrame,
                 capital: float = 1_000_000, costs: Costs = Costs(),
                 max_weight: float = 0.10, max_leverage: float = 1.0):
        self.px = prices.sort_index()
        self.target = target.sort_index()
        self.capital = capital
        self.costs = costs
        self.max_weight = max_weight
        self.max_leverage = max_leverage

    def run(self) -> pd.DataFrame:
        dates = self.px.index.get_level_values(0).unique().sort_values()
        symbols = self.px.index.get_level_values(1).unique()

        cash = self.capital
        shares = pd.Series(0.0, index=symbols)
        prev_close = pd.Series(np.nan, index=symbols)
        records = []
        traded_today = 0.0

        for i, date in enumerate(dates):
            day = self.px.loc[date].reindex(symbols)
            open_px = day["open"]
            close_px = day["close"]

            # ---- 1. 开盘：执行昨日信号 ----
            traded_today = 0.0
            if i > 0:
                prev_date = dates[i - 1]
                if prev_date in self.target.index.get_level_values(0):
                    w = self.target.loc[prev_date].reindex(symbols).fillna(0.0)
                    w = w.clip(-self.max_weight, self.max_weight)
                    if w.abs().sum() > self.max_leverage:
                        w *= self.max_leverage / w.abs().sum()

                    equity_open = cash + (shares * open_px.fillna(prev_close)).sum()
                    desired = (w * equity_open / open_px).replace([np.inf, -np.inf], np.nan)

                    for sym in symbols:
                        if not np.isfinite(open_px.get(sym, np.nan)) or open_px[sym] <= 0:
                            continue
                        if day.loc[sym, "volume"] <= 0:
                            continue
                        delta = desired.get(sym, 0) - shares[sym]
                        if abs(delta * open_px[sym]) < 1000:
                            continue

                        side = "buy" if delta > 0 else "sell"
                        px = open_px[sym] * (1 + self.costs.slippage * (1 if side == "buy" else -1))
                        fee = abs(delta * px) * (self.costs.commission +
                                                 (self.costs.stamp_tax if side == "sell" else 0))
                        cash -= delta * px + fee
                        shares[sym] += delta
                        traded_today += abs(delta * px)

            # ---- 2. 收盘：盯市 ----
            equity = cash + (shares * close_px.fillna(prev_close)).sum()
            gross = (shares * close_px.fillna(prev_close)).abs().sum()
            records.append({"date": date, "equity": equity, "cash": cash,
                            "gross": gross, "traded": traded_today})
            prev_close = close_px.combine_first(prev_close)

        out = pd.DataFrame(records).set_index("date")
        out["returns"] = out["equity"].pct_change().fillna(0)
        out["exposure"] = out["gross"] / out["equity"]
        out["turnover"] = out["traded"] / out["equity"]
        return out

这个引擎有几个刻意的设计，值得注意：

  • 信号日与执行日分离：target 在 T 日收盘生成，T+1 开盘执行。这一行代码消灭了 80% 的前视偏差。
  • 按开盘价重算股数：不是简单地按目标权重买入，而是用「当前权益 ÷ 开盘价」算目标股数，避免权重漂移。
  • 显式扣费：佣金、印花税、滑点分别计算，不混在一起。
  • 最小交易额过滤：< 1000 元的调仓不执行，避免不现实的碎股交易。
它仍然不完美

它没有模拟：部分成交、涨跌停无法成交、停牌、T+1 限制、以及冲击成本随订单量变化。 在生产环境里，这些都要补上。但即使只有这些，它已经比 90% 的「按收盘价全仓成交」 的回测诚实得多。

假设你有两个策略，各自的年化收益都是 10%，波动都是 20%，相关性为 0。 各投一半，组合收益还是 10%，但波动降到 14.1%。你什么都没做，夏普从 0.5 变成了 0.71。 这就是分散的魔力——它是金融里唯一「免费的午餐」。

但这顿午餐有条件：相关性必须真的低，而且必须在你需要它低的时候也低。 而市场最擅长的，就是在你最需要分散的时候，让所有东西一起跌。

9.1分散的数学：为什么 1+1 < 2

对于 N 个等权、同波动率 σ、两两相关性 ρ 的资产，组合波动率是：

σp = σ · √( 1/N + (1 − 1/N)·ρ ) (9.1)

当 N → ∞，σp → σ√ρ。这就是「不可分散的风险」。 如果 ρ = 0.5，你最多只能把波动降到原来的 70.7%，再怎么加资产都没用。

9.2马科维茨：优美的理论，糟糕的实践

均值-方差优化要解决的问题是：在给定风险下最大化收益。数学上很干净：

maxw   wᵀμ − (λ/2)·wᵀΣw    s.t.   Σwi = 1 (9.2)

解出来是 w* ∝ Σ⁻¹μ。漂亮，但实战中经常灾难性失败。 原因只有一个：它把估计误差当成了真实信号。

误差最大化器

Michaud 把均值-方差优化称为「误差最大化器」（error maximizer）。 原因：优化器会超配那些被高估收益、低估风险的资产， 而估计误差恰好让某些资产看起来「高收益低风险」。结果你买到的是噪声，不是 alpha。

三个补救办法

  1. 不要优化 μ。用等权、风险平价、或简单的打分权重，只优化风险。
  2. 收缩协方差矩阵。Ledoit-Wolf 收缩把样本协方差向结构化矩阵拉，降低估计误差。
  3. 加约束。单资产上限、行业中性、换手约束。约束越强，优化器越难「发挥想象力」。

9.3风险平价：不预测收益的配置

风险平价（Risk Parity）的核心思想是：不猜收益，只分配风险。 每个资产对组合总风险的贡献相等。这样你不需要估计 μ，只需要估计 Σ——而 Σ 的估计误差小得多。

风险贡献的定义是：

RCi = wi · (Σw)i / √(wᵀΣw) (9.3)

目标是让所有 RCi 相等。这个问题没有解析解，但可以用迭代法快速求解：

risk_parity.py
import numpy as np


def risk_contributions(w: np.ndarray, cov: np.ndarray) -> np.ndarray:
    port_var = w @ cov @ w
    marginal = cov @ w
    return w * marginal / np.sqrt(port_var)


def erc_weights(cov: np.ndarray, iters: int = 500, tol: float = 1e-10) -> np.ndarray:
    """等风险贡献（Equal Risk Contribution）权重，用循环坐标下降求解。"""
    n = cov.shape[0]
    w = np.ones(n) / n
    for _ in range(iters):
        prev = w.copy()
        for i in range(n):
            # 目标：RC_i = σ / n，即 w_i·(Σw)_i = σ² / n
            target = (w @ cov @ w) / n
            a = cov[i, i]
            b = (cov[i] @ w) - cov[i, i] * w[i]
            # 解 a·w_i² + b·w_i − target = 0，取正根
            disc = b * b + 4 * a * target
            w[i] = (-b + np.sqrt(max(disc, 0))) / (2 * a)
        w = np.clip(w, 0, None)
        w /= w.sum()
        if np.max(np.abs(w - prev)) < tol:
            break
    return w


def portfolio_vol(w: np.ndarray, cov: np.ndarray) -> float:
    return float(np.sqrt(w @ cov @ w))
风险平价的隐含杠杆

债券波动低，股票波动高。要让两者风险贡献相等，债券的权重会非常大（可能 80%）。 为了让整体收益可接受，通常会对整个组合加杠杆。这就是「风险平价基金」的典型结构。 对个人来说，不加杠杆的风险平价依然有意义：它会让你的组合更稳， 只是收益也会更低。

9.4波动率目标化：让曲线变平滑

这是实战中最有用的技术之一，原理简单到一句话： 波动高的时候减仓，波动低的时候加仓，让组合的波动率保持恒定。

wt = min( Lmax , σtarget / σ̂t ) (9.4)

假设目标波动 10%，当前估计波动 20%，则仓位系数 = 0.5。 如果波动降到 8%，系数 = 1.25（但受最大杠杆限制）。

vol_target.py
import numpy as np
import pandas as pd


def vol_target_returns(returns: pd.Series, target: float = 0.10,
                       halflife: int = 20, max_leverage: float = 2.0,
                       periods: int = 252) -> pd.Series:
    """对单策略做波动率目标化。returns 为日频策略收益。"""
    vol = returns.ewm(halflife=halflife, adjust=False).std() * np.sqrt(periods)
    scale = (target / vol).clip(upper=max_leverage)
    scale = scale.shift(1)          # 用昨天的波动决定今天的仓位，避免前视
    return returns * scale


def compare(returns: pd.Series):
    raw = returns.dropna()
    vt = vol_target_returns(returns).dropna()
    out = pd.DataFrame({
        "raw": [raw.mean() * 252, raw.std() * np.sqrt(252),
                raw.mean() / raw.std() * np.sqrt(252)],
        "vol_target": [vt.mean() * 252, vt.std() * np.sqrt(252),
                       vt.mean() / vt.std() * np.sqrt(252)],
    }, index=["ann_ret", "ann_vol", "sharpe"])
    return out

波动率目标化的效果通常是：收益略降，波动大幅降，夏普上升，最大回撤显著改善。 它不创造 alpha，但它让同样的 alpha 变得更容易持有。

一个副作用

波动率目标化在危机初期会自动减仓，这很好；但当波动率突然飙升又迅速回落时， 它会在低点减仓、高点加仓，产生「波动率陷阱」损耗。 解决办法：对波动率估计做平滑，或者设置调仓阈值（变化超过 20% 才调整）。

9.5风险度量：VaR、CVaR 与压力测试

VaR：在 95% 置信度下，我最多亏多少？

VaRα = −Quantile1−α(R) (9.5)

VaR 的问题是：它只告诉你「阈值在哪」，不告诉你「超过阈值会有多惨」。 而且它不满足次可加性——两个 VaR 为 100 的组合，合并后 VaR 可能大于 200。

CVaR：超过阈值后的平均损失

CVaRα = −E[ R | R < −VaRα ] (9.6)

CVaR（也叫 Expected Shortfall）衡量尾部损失的期望值，是更稳健的风险度量。 监管机构（巴塞尔协议）已经从 VaR 转向 CVaR。

压力测试：不看历史，看假设

VaR 和 CVaR 都基于历史分布，而历史不会重复。压力测试问的是： 如果发生 X，我会怎样？

  • 历史情景：2008 金融危机、2015 股灾、2020 年 3 月、2022 年加息。
  • 假设情景：股指单日 −10%、利率 +200bps、相关性全部升到 0.9。
  • 反向压力测试：什么情况下我会亏掉 50%？（然后问这个情况有多可能）
相关性假设是压力测试的核心

大多数风险模型在正常时期表现良好，在危机时期集体失效，因为它们假设相关性稳定。 压力测试时，应该手动把相关性调高（比如全部设为 0.8）， 再看组合的损失。这比任何 VaR 模型都更接近真相。

9.6尾部与凸性：为最坏的情况付费

如果你的策略是负偏的（卖期权、carry、杠杆套利），你需要一些「凸性」来对冲尾部。 常见做法：

  • 买入虚值看跌期权：成本是持续的保费，收益是危机时的爆发。
  • 持有少量趋势策略：趋势策略在危机中往往正收益（因为跌势持续）。
  • 保留现金：最朴素的凸性，代价是机会成本。

这类对冲在 90% 的时间里都在亏钱，只有在 10% 的时间里救命。 它的心理难度极高——你会在连续亏损 18 个月后想放弃它，而那往往是它最该被保留的时候。

9.7本章陷阱清单

  • 用样本协方差直接做均值-方差优化。
  • 以为「持有 50 只股票」就是分散。
  • 用长期平均相关性做风险模型，忽略危机时的相关性上升。
  • 波动率目标化时用了当天的波动率（前视）。
  • 把 VaR 当成「最大可能损失」。
  • 压力测试只跑历史情景，不做假设情景。
  • 在负偏策略上不加尾部对冲，还加杠杆。

10.1交易成本的解剖

学术上有一个统一的概念：实施差额（implementation shortfall，IS）。 它衡量的是「决策时的理论价格」与「实际成交均价」之间的差距。

IS = (实际成交均价 − 决策价格) × 方向 × 数量 (10.1)

IS 可以分解成四块，每一块对应不同的优化手段：

成分来源优化手段
显性成本佣金、税费、交易所规费选低费率券商；减少交易频率
价差成本跨过买卖价差用限价单、做被动成交
冲击成本你的订单改变了价格拆单、降低参与率、拉长时间
时机风险等待期间价格漂移加快执行、使用短期 alpha 信号

注意最后两项是此消彼长的：拆得越细，冲击越小，但暴露在价格漂移下的时间越长。 这就是执行的 core trade-off。

10.2冲击的平方根定律

这是市场微观结构里最稳健的经验规律之一：价格冲击大致与订单量的平方根成正比， 而不是线性。

Impact ≈ Y · σ · √( Q / V ) (10.2)

σ 为日波动率，Q 为你的订单量，V 为日均成交量，Y 为经验常数（约 0.5–1）。

含义非常反直觉：订单量翻 4 倍，冲击只翻 2 倍。 这解释了为什么大资金反而有优势——它们的单笔成本占比更低。 也解释了为什么小资金不该模仿大资金的「慢慢建仓」：你的冲击本来就小， 等待反而带来更多时机风险。

10.3Almgren-Chriss：最优执行轨迹

1999 年，Almgren 和 Chriss 把执行问题形式化为一个优化问题： 在「冲击成本」与「时机风险」之间找平衡。

min   E[Cost] + λ · Var[Cost] (10.3)

λ 是风险厌恶系数。λ = 0 时，你只关心成本，会无限拆单（TWAP）； λ → ∞ 时，你只关心风险，会立刻全部成交。

在永久冲击与临时冲击都线性的假设下，最优持仓路径是指数衰减：

x(t) = X · sinh( κ(T − t) ) / sinh( κT )   ,   κ = √(λσ²/η) (10.4)

κ 越大（风险厌恶高、波动大、冲击系数小），衰减越快，越接近「立刻成交」； κ → 0 时退化为线性，即 TWAP。

almgren_chriss.py
import numpy as np


def ac_trajectory(shares: int, horizon: int, sigma: float,
                  eta: float, lam: float) -> np.ndarray:
    """返回每个时间步结束时剩余股数（长度 horizon+1）。
    sigma: 每期价格波动率；eta: 临时冲击系数；lam: 风险厌恶。
    """
    if lam <= 0:
        # 退化为 TWAP
        return np.linspace(shares, 0, horizon + 1)

    kappa = np.sqrt(lam * sigma ** 2 / eta)
    t = np.arange(horizon + 1)
    remaining = shares * np.sinh(kappa * (horizon - t)) / np.sinh(kappa * horizon)
    return remaining


def simulate_cost(trajectory: np.ndarray, sigma: float, eta: float,
                  gamma: float, seed: int = 0) -> dict:
    """模拟执行成本：临时冲击 + 永久冲击 + 随机漂移。

    eta   : 临时冲击系数（单位：价格 / 股）
    gamma : 永久冲击系数
    sigma : 每期价格波动率
    """
    rng = np.random.default_rng(seed)
    trades = -np.diff(trajectory)          # 每期买入量
    price = 100.0
    arrival = price
    notional, qty, temp_cost = 0.0, 0.0, 0.0

    for q in trades:
        if q <= 0:
            continue
        exec_px = price + eta * q          # 临时冲击：成交瞬间的价格劣化
        notional += exec_px * q
        qty += q
        temp_cost += eta * q * q
        price += gamma * q                 # 永久冲击：改变后续所有成交价
        price *= 1 + sigma * rng.standard_normal() * 0.1

    avg_px = notional / qty
    return {
        "arrival": arrival,
        "avg_price": avg_px,
        "total_bps": (avg_px - arrival) / arrival * 1e4,
        "temp_cost": temp_cost,
    }

这个模型的问题

AC 假设冲击是线性的、波动率是恒定的、且你只关心均值-方差。 现实中冲击是非线性的（平方根），波动率会变，而且你往往还有短期 alpha 信号 （「现在买比等会儿买更好」）。所以实战中的执行算法通常是 AC 的骨架 + 实时信号调整 + 硬约束（参与率上限、最短/最长执行时间）。

10.5滑点：怎么测量，怎么归因

滑点不是一个数字，是一个分布。你必须记录每一笔交易的：

  • 决策价格（信号生成时的中间价）
  • 下单时间与下单价格
  • 成交时间、成交均价、成交量
  • 同期市场的中间价变化（用于分离「市场漂移」和「你的冲击」）
tca.py
import pandas as pd

def tca(trades: pd.DataFrame) -> pd.DataFrame:
    """交易成本分析。trades 需含:
    side, decision_px, arrival_mid, exec_px, qty, market_mid_at_end
    """
    df = trades.copy()
    sign = df["side"].map({"buy": 1, "sell": -1})

    df["total_bps"] = sign * (df["exec_px"] - df["decision_px"]) / df["decision_px"] * 1e4
    df["delay_bps"] = sign * (df["arrival_mid"] - df["decision_px"]) / df["decision_px"] * 1e4
    df["exec_bps"] = sign * (df["exec_px"] - df["arrival_mid"]) / df["arrival_mid"] * 1e4
    df["market_bps"] = sign * (df["market_mid_at_end"] - df["arrival_mid"]) / df["arrival_mid"] * 1e4
    # 执行超额 = 总成本 − 市场漂移（负值代表你比市场做得好）
    df["excess_bps"] = df["exec_bps"] - df["market_bps"]

    summary = df.groupby("side")[["total_bps", "delay_bps", "exec_bps",
                                  "market_bps", "excess_bps"]].agg(["mean", "count"])
    return df, summary

这个分解能回答一个关键问题：我的成本，是因为市场跑了，还是因为我太笨？ 如果 delay_bps 很大，说明你决策太慢或下单延迟高； 如果 exec_bps 远大于 market_bps，说明你的冲击或价差成本过高。

10.6容量：一个策略最多能装多少钱

容量（capacity）是指：在成本吃掉全部 alpha 之前，这个策略最多能管理多少资金。 估算方法：

容量 ≈ (单笔可承受成本对应的订单量) × 每年可交易次数 × 持仓数 (10.5)

更实用的算法：把资金量从 100 万逐步放大到 10 亿，每个规模跑一次带冲击模型的回测， 画出「资金量 → 净夏普」曲线。曲线穿过 0 的那个点，就是容量上限。

容量的隐形杀手

很多策略在小资金时夏普 1.5，到 5000 万时降到 0.8，到 2 亿时归零。 这不是线性衰减——因为冲击是平方根，而 alpha 是线性的。 如果你打算管理别人的钱，容量测试比历史收益重要十倍。

10.7本章陷阱清单

  • 回测里假设零滑点，或者用固定的 1bp 滑点。
  • 用收盘价成交，忽略集合竞价的特殊性。
  • 大单一次性市价成交，不拆单。
  • 拆单拆得太细，暴露在价格漂移下太久。
  • 不记录决策价格，导致无法做成本归因。
  • 用「成交均价 vs VWAP」考核执行，但 VWAP 本身可以被操纵。
  • 不做容量测试就放大资金。

  • 实施差额 = 显性成本 + 价差 + 冲击 + 时机风险。

实盘系统

回测是理想世界，实盘是分布式系统。你会遇到重复下单、断线重连、部分成交、 行情延迟、券商接口抽风、以及凌晨三点的告警电话。 这一章讲怎么造一个「出错时不会亏大钱」的系统——重点不是功能，是失效模式。

11.2状态机：订单的一生

订单不是「发出去就完了」。它有明确的状态转移，每一次转移都必须被记录：

order_state.py
from enum import Enum

class OrderState(Enum):
    CREATED = "created"          # 本地创建
    SUBMITTING = "submitting"    # 已发送，等待确认
    ACKED = "acked"              # 交易所已接受
    PARTIAL = "partial"          # 部分成交
    FILLED = "filled"            # 全部成交
    CANCELING = "canceling"      # 撤单请求已发
    CANCELED = "canceled"        # 已撤销
    REJECTED = "rejected"        # 被拒绝
    UNKNOWN = "unknown"          # 状态未知（断线/超时）

# 合法转移
TRANSITIONS = {
    OrderState.CREATED:    {OrderState.SUBMITTING},
    OrderState.SUBMITTING: {OrderState.ACKED, OrderState.REJECTED, OrderState.UNKNOWN},
    OrderState.ACKED:      {OrderState.PARTIAL, OrderState.FILLED,
                            OrderState.CANCELING, OrderState.CANCELED},
    OrderState.PARTIAL:    {OrderState.PARTIAL, OrderState.FILLED, OrderState.CANCELING},
    OrderState.CANCELING:  {OrderState.CANCELED, OrderState.FILLED},
    OrderState.UNKNOWN:    {OrderState.ACKED, OrderState.REJECTED, OrderState.CANCELED},
}

def can_transition(src: OrderState, dst: OrderState) -> bool:
    return dst in TRANSITIONS.get(src, set())

UNKNOWN 是最危险的状态。网络超时后，你不知道订单是否到达交易所。 此时正确的做法不是重发（可能重复下单），而是： 先查询，查询失败则撤单，撤单失败则人工介入。 这条规则能避免 90% 的「幽灵订单」事故。

11.3幂等：重复请求不能重复下单

分布式系统的经典问题：客户端超时重试，服务端收到了两次请求。 在交易里，这意味着买了两倍。

idempotent.py
import hashlib
import sqlite3

def client_order_id(strategy: str, symbol: str, side: str,
                    target_qty: int, trade_date: str) -> str:
    """由业务语义生成唯一 ID：同一天、同一策略、同一标的、同一目标，
    重复调用会得到同一个 ID，从而被去重。"""
    raw = f"{strategy}|{symbol}|{side}|{target_qty}|{trade_date}"
    return hashlib.sha256(raw.encode()).hexdigest()[:24]


def submit_once(conn: sqlite3.Connection, coid: str, payload: dict) -> bool:
    """返回 True 表示本次真的提交了；False 表示已存在，跳过。"""
    try:
        conn.execute(
            "INSERT INTO orders(client_order_id, payload, state) VALUES (?, ?, ?)",
            (coid, str(payload), "created"),
        )
        conn.commit()
        return True
    except sqlite3.IntegrityError:
        return False          # 主键冲突 = 已经提交过

注意这个 ID 的生成方式：它不是随机 UUID，而是由业务语义决定的。 这样即使进程重启、重试三次，只要「策略 + 标的 + 方向 + 目标数量 + 日期」相同， ID 就相同，数据库主键会拦住重复。

11.4风控：硬约束与熔断

风控分两层：事前（下单前检查）和事中/事后（监控与熔断）。 事前的检查必须是同步的、阻塞的——不通过就不许发单。

from dataclasses import dataclass
import time


@dataclass
class RiskLimits:
    max_order_pct: float = 0.05
    max_symbol_pct: float = 0.15
    max_gross: float = 1.0
    daily_loss_limit: float = 0.03
    max_drawdown: float = 0.15
    max_orders_per_min: int = 20


class RiskGate:
    def __init__(self, limits: RiskLimits):
        self.limits = limits
        self.day_start_equity = None
        self.peak_equity = None
        self.order_times = []
        self.halted = False

    def on_new_day(self, equity: float):
        self.day_start_equity = equity
        self.peak_equity = max(self.peak_equity or equity, equity)
        self.halted = False

    def check(self, order_value: float, symbol_value: float, gross_value: float,
              equity: float, now: float | None = None) -> tuple[bool, str]:
        L = self.limits
        now = now or time.time()

        if self.halted:
            return False, "系统已熔断"

        # 日亏损
        if self.day_start_equity and equity / self.day_start_equity - 1 <= -L.daily_loss_limit:
            self.halted = True
            return False, f"触发日亏损熔断"

        # 回撤
        self.peak_equity = max(self.peak_equity or equity, equity)
        if equity / self.peak_equity - 1 <= -L.max_drawdown:
            self.halted = True
            return False, "触发回撤熔断"

        # 仓位
        if order_value > equity * L.max_order_pct:
            return False, "单笔超限"
        if symbol_value > equity * L.max_symbol_pct:
            return False, "单标的超限"
        if gross_value > equity * L.max_gross:
            return False, "总仓位超限"

        # 频率
        self.order_times = [t for t in self.order_times if now - t < 60]
        if len(self.order_times) >= L.max_orders_per_min:
            return False, "下单频率超限"
        self.order_times.append(now)

        return True, "ok"
Kill Switch 必须是物理的

熔断逻辑写在代码里，就有 bug 的可能。成熟的团队会有一个独立于交易进程的 开关：一个文件、一个 HTTP 端点、或者一个物理按钮。它直接让执行进程停止发单， 不依赖任何策略逻辑。如果只有代码里的熔断，你就是在用同一套 bug 保护自己。

11.5对账：每天必须做的一件事

收盘后，你的系统认为的持仓，必须和券商返回的持仓完全一致。 不一致的原因可能是：成交回报丢失、部分成交未处理、分红送股、手工操作。

reconcile.py
def reconcile(local: dict[str, int], broker: dict[str, int]) -> dict:
    """对比本地与券商的持仓，返回差异。"""
    symbols = set(local) | set(broker)
    diffs = {}
    for s in symbols:
        l, b = local.get(s, 0), broker.get(s, 0)
        if l != b:
            diffs[s] = {"local": l, "broker": b, "diff": b - l}
    return diffs


def assert_flat_if_halted(diffs: dict, halted: bool):
    """如果系统熔断，必须确认所有仓位已平。"""
    if halted and diffs:
        raise RuntimeError(f"熔断后仍有持仓差异，需人工介入: {diffs}")

对账不只是「看一眼」。它应该是一个硬性流程：不一致就告警， 连续两天不一致就停止交易。因为持仓不一致意味着你的所有风险计算都是错的。

11.6可观测性：你该监控什么

心跳

策略进程、行情连接、交易连接，各自每分钟打一次心跳。缺失 2 分钟告警。

延迟

行情到达 → 信号计算 → 下单 → 回报，每一段的 P50/P99。P99 恶化往往是事故前兆。

订单健康度

拒单率、撤单率、成交率、平均滑点。拒单率突然上升，通常是参数或接口出了问题。

持仓与风险

实时仓位、行业暴露、beta、VaR。与目标偏离超过阈值就告警。

盈亏

当日 PnL、累计 PnL、与回测预期的偏离。偏离过大说明市场结构变了。

数据质量

缺失行情数、异常价格数、时间戳延迟。数据问题往往先于交易问题出现。

告警的设计原则

告警必须可执行。每一条告警都应该对应一个明确的动作（重启、平仓、检查网络、忽略）。 如果一个告警你每次都忽略，就删掉它——它只会训练你忽略所有告警。 另外，把「严重」和「警告」分开：严重告警打电话，警告发消息。

11.7部署：让错误无法上线

  • 版本固定：策略、参数、依赖版本全部写入配置文件，随订单一起记录。这样任何一笔交易都能追溯到当时的代码版本。
  • 灰度：新版本先跑纸上交易（paper trading）两周，再用 10% 资金，最后全量。
  • 回放：把历史行情重放给新版本，对比输出是否与旧版本一致（除了预期的改动）。
  • 一键回滚：保留上一个可用版本，出问题 30 秒内切回。
  • 时间同步：所有机器用 NTP 同步，日志时间戳必须可比。

机器学习
机会与幻觉

机器学习在金融里既被高估，也被低估。被高估的是「模型能发现规律」， 被低估的是「特征工程和验证设计决定一切」。 这一章不讲调参，讲三件事：金融数据的特殊性、标签怎么造、以及为什么交叉验证在这里会骗你。

在图像识别里，你有百万张标注图片，规律是稳定的，信噪比很高。 在金融里，你只有几千个样本，规律在变，信噪比低到 0.05。 把 ImageNet 的方法直接搬过来，你会得到极高的训练集准确率，和归零的实盘收益。

但机器学习仍然有价值——不是因为它能「预测价格」，而是因为它擅长 在高维、非线性、有交互的数据里找微弱的统计规律。前提是，你必须诚实地设计验证。

12.1金融数据的四个特殊性

① 信噪比极低

日频收益的可预测部分通常小于 5%。R² = 0.01 已经值得研究。这意味着模型很容易拟合噪声。

② 样本少且不独立

10 年日频数据只有 2500 个点，且高度自相关。有效样本量可能只有几百。

③ 非平稳

市场结构会变：监管、参与者、技术。2015 年有效的规律，2025 年可能反向。

④ 标签有重叠

「未来 20 日收益」在相邻日期之间高度重叠，破坏了交叉验证的独立性假设。

这四点共同导致一个结论：在金融里，验证设计比模型选择重要十倍。 一个线性模型 + 正确的 purged CV，通常胜过一个深度网络 + 随机 K 折。

12.2标签：你到底在预测什么

最朴素：未来收益

yt = (Pt+h / Pt) − 1 (12.1)

问题是：收益分布厚尾，少数极端值会主导损失函数；而且 h 越长，样本越少、越不独立。

更好：横截面排序

不预测「涨多少」，而预测「比别的股票涨得多」。把 y 转成横截面分位数或 rank， 消除了市场整体涨跌的影响，也让分布更接近均匀。

更适合交易：三重障碍法

López de Prado 提出的 triple barrier：给每个样本设三道障碍—— 上轨（止盈）、下轨（止损）、时间（到期）。看价格先碰到哪一个，据此打标签。

triple_barrier.py
import numpy as np
import pandas as pd


def triple_barrier_labels(prices: pd.Series, vol_window: int = 20,
                          barrier_mult: float = 2.0, horizon: int = 20,
                          up: float | None = None, down: float | None = None):
    """返回标签与触碰时间。
    label: +1 先触上轨, -1 先触下轨, 0 到期未触碰
    """
    vol = prices.pct_change().rolling(vol_window).std()
    labels, touch_idx = [], []

    for i in range(len(prices) - horizon):
        p0 = prices.iloc[i]
        sigma = vol.iloc[i]
        if not np.isfinite(sigma):
            labels.append(np.nan); touch_idx.append(i)
            continue

        upper = p0 * (1 + (up if up is not None else barrier_mult * sigma))
        lower = p0 * (1 - (down if down is not None else barrier_mult * sigma))
        window = prices.iloc[i + 1: i + 1 + horizon]

        hit_up = window[window >= upper]
        hit_dn = window[window <= lower]
        t_up = hit_up.index[0] if len(hit_up) else None
        t_dn = hit_dn.index[0] if len(hit_dn) else None

        if t_up and (not t_dn or t_up <= t_dn):
            labels.append(1); touch_idx.append(prices.index.get_loc(t_up))
        elif t_dn:
            labels.append(-1); touch_idx.append(prices.index.get_loc(t_dn))
        else:
            labels.append(0); touch_idx.append(i + horizon)

    return pd.Series(labels, index=prices.index[:len(labels)]), touch_idx

12.3特征：从「原始数据」到「信息」

特征工程是量化 ML 的核心，模型只是最后一层。好的特征通常来自三个方向：

类别例子注意
时序特征过去 N 日收益、波动率、成交量变化、RSI必须用 shift 保证只用历史
横截面特征行业内排名、市值分位、估值分位每个日期内计算，不能跨期
交互特征动量 × 波动率、价值 × 质量容易过拟合，要有经济逻辑
另类特征新闻情绪、搜索指数、供应链覆盖率与时点最难处理
特征里的三个泄漏源

① 用全样本做标准化（均值、方差包含了未来）；
② 用未来数据填充缺失值（前向填充用错了方向）；
③ 特征的计算窗口跨越了标签期（比如用 t+5 的数据算 t 的特征）。

12.4验证：为什么随机 K 折会骗你

标准 K 折把数据随机分成 K 份，轮流用 K−1 份训练、1 份测试。 在图像数据里这没问题，因为样本独立。但在时间序列里，它会造成两种泄漏：

  • 未来信息泄漏：训练集里包含了测试集之后的数据。
  • 标签重叠：相邻样本的标签共享同一段未来收益。

结果是：你的交叉验证分数会非常漂亮，实盘一塌糊涂。正确做法是 Purged K-Fold + Embargo（第八章已给代码），或者直接用 walk-forward。

ml_pipeline.py
import numpy as np
import pandas as pd
from sklearn.ensemble import HistGradientBoostingRegressor

from purged_cv import purged_splits


def cross_sectional_rank(df: pd.DataFrame, col: str) -> pd.Series:
    """在每个日期内把特征转成 0~1 的分位数，消除量纲与市场整体影响。"""
    return df.groupby("date")[col].rank(pct=True)


def build_features(panel: pd.DataFrame) -> pd.DataFrame:
    df = panel.sort_values(["symbol", "date"]).copy()
    g = df.groupby("symbol")

    df["ret_1"] = g["close"].pct_change(1)
    df["ret_20"] = g["close"].pct_change(20)
    df["vol_20"] = g["ret_1"].transform(lambda s: s.rolling(20).std())
    df["volume_ratio"] = df["volume"] / g["volume"].transform(lambda s: s.rolling(20).mean())
    df["ma_gap"] = df["close"] / g["close"].transform(lambda s: s.rolling(60).mean()) - 1

    # 横截面标准化（每个日期内）
    for c in ["ret_20", "vol_20", "volume_ratio", "ma_gap"]:
        df[c + "_cs"] = cross_sectional_rank(df, c)

    # 标签：未来 5 日收益的横截面排名
    df["fwd_ret"] = g["close"].shift(-5) / df["close"] - 1
    df["label"] = df.groupby("date")["fwd_ret"].rank(pct=True)
    return df.dropna()


FEATURES = ["ret_1", "ret_20_cs", "vol_20_cs", "volume_ratio_cs", "ma_gap_cs"]


def train_with_purged_cv(df: pd.DataFrame, n_splits: int = 5):
    dates = df["date"].unique()
    date_idx = {d: i for i, d in enumerate(dates)}
    df = df.assign(t=df["date"].map(date_idx))

    scores = []
    for train_t, test_t in purged_splits(len(dates), n_splits,
                                         label_horizon=5, embargo=2):
        train = df[df["t"].isin(train_t)]
        test = df[df["t"].isin(test_t)]
        if len(train) < 100 or len(test) < 20:
            continue

        model = HistGradientBoostingRegressor(
            max_depth=4, max_iter=200, learning_rate=0.05,
            l2_regularization=1.0, random_state=0,
        )
        model.fit(train[FEATURES], train["label"])
        pred = model.predict(test[FEATURES])

        # 用 Spearman 相关衡量排序能力（IC）
        ic = pd.Series(pred).corr(pd.Series(test["label"].values), method="spearman")
        scores.append(ic)

    return np.mean(scores), np.std(scores)

12.5模型选择：什么时候用什么

模型优势劣势适用
线性 / Ridge稳定、可解释、样本需求小无法捕捉非线性与交互因子合成、基准模型
GBDT / 树模型自动处理非线性、缺失值、交互容易过拟合、外推能力差横截面选股的主力
神经网络能学复杂模式、适合大数据样本需求大、难解释、易过拟合高频、另类数据
集成降低方差、提升稳健性复杂度上升多模型融合

在金融里，简单模型 + 好特征 + 正确验证，通常打败复杂模型 + 烂验证。 因为你的瓶颈不是模型容量，是信噪比。

正则化就是先验

在低信噪比环境里，任何「让模型更灵活」的操作都在增加过拟合风险。 L2 正则、浅树、早停、特征少而精——这些约束不是妥协，是把「简单」作为一种先验。 市场大概率是简单的，只是噪声很大。

12.6特征重要性 ≠ 因果

树模型的特征重要性告诉你「这个特征在训练集里对降低损失有帮助」， 不告诉你「它对未来有效」，更不告诉你「它和收益有因果关系」。

  • 重要性可能来自泄漏（某个特征偷偷包含了未来信息）。
  • 重要性可能来自共线性（两个特征高度相关，重要性被随机分配给其中一个）。
  • 重要性在不同时间段可能完全不同（非平稳）。

正确做法：用样本外的置换重要性（permutation importance）， 并且分年度看它是否稳定。一个只在 2020 年重要的特征，不值得依赖。

12.7强化学习：为什么很难落地

RL 在游戏里很成功，因为环境可以无限次重置、奖励明确、状态可观测。 金融不满足这三条：

  • 不能重置：你只有一条历史路径，样本量有限。
  • 奖励有噪声：赚钱可能是运气，模型会学到错误的行为。
  • 部分可观测：你不知道其他参与者的意图。
  • 非平稳：对手会适应你，市场结构会变。

RL 在金融里真正有用的场景，通常是执行优化（在模拟器里可以大量试错）， 而不是「让 AI 自己学会炒股」。

12.8本章陷阱清单

  • 用随机 K 折做时间序列交叉验证。
  • 用全样本统计量做特征标准化。
  • 标签期与特征窗口重叠，造成泄漏。
  • 用训练集的 R² 或准确率评价模型。
  • 特征重要性当作因果解释。
  • 在只有 2000 个样本的数据上训练深度网络。
  • 忽略交易成本，只看预测精度。
  • 相信「AI 选股」的黑箱，不做归因。

有一个实验很有名：给投资者看两种基金，A 每年稳定 8%，B 平均 10% 但每隔几年亏 20%。 大多数人选 A，尽管 B 的长期收益更高。这不是愚蠢，是人类对痛苦的权重天然高于快乐。

交易系统必须为这个事实设计，而不是假设自己能克服它。你需要的不是「更强大的意志力」， 是让正确的事变得容易，让错误的事变得困难。

13.1过程与结果：唯一重要的思维切换

单笔交易的结果是随机的。一个好策略也可能连续亏 10 次，一个坏策略也可能连赢 20 次。 如果你用结果评价决策，你会系统性地学到错误的东西。

概率思维的三句话

① 我做的每一个决策，都只是在调整概率，不是在决定结果。
② 一次亏损不证明我错了，一次盈利不证明我对了。
③ 我唯一能控制的，是决策过程的质量和下注的大小。

这不是心灵鸡汤，它有非常具体的实践含义：你的复盘对象应该是「决策」，不是「盈亏」。 一笔亏损的交易，如果它符合规则、仓位合理、执行到位，它就是一笔好交易。 一笔盈利的交易，如果是靠加仓死扛换来的，它就是一笔坏交易——而且它会更危险， 因为它强化了坏习惯。

13.4策略的生命周期

阶段一：研究（3–6 个月）

目标不是找到「最好的策略」，而是找到一个你能解释、能复现、能承受的策略。 通过标准：样本外夏普 > 0.5、扣成本后仍为正、参数不敏感、逻辑可解释。

阶段二：纸面交易（1–3 个月）

不投钱，但每天按真实价格记录信号与「如果成交」的结果。 这个阶段验证的不是策略，是你的系统和你的执行力： 数据有没有延迟？信号会不会漏？你能不能每天按时操作？

阶段三：小资金（3–6 个月）

用你「亏光也不影响生活」的金额。这个阶段的目的是暴露真实成本与心理反应。 很多人会在这里发现：回测里的滑点是 5bps，实际是 25bps。

阶段四：放大

逐步加资金，每次加仓后观察 1–2 个月。加仓的节奏应该慢于你的信心增长速度—— 因为信心通常跑得比证据快。

阶段五：衰减与退役

策略会失效。原因可能是拥挤、监管、市场结构变化。你需要事先定义退役条件：

  • 滚动 12 个月收益低于历史 5% 分位。
  • 连续 18 个月跑输基准。
  • 核心假设被证伪（比如因子逻辑不再成立）。
  • 回撤超过历史最大回撤的 1.5 倍。
最难的部分

退役条件必须在策略赚钱的时候写下。因为亏钱的时候，你会找各种理由延长它： 「再给它三个月」「这次是特殊情况」「长期看还是有效的」。 这些理由可能都对，但你没有能力在压力下客观判断——所以让规则替你判断。

13.5资金曲线管理：把策略当员工

一个有用的心理模型：把每个策略当成一个员工。你要做的不是「相信他」， 而是「给他设定 KPI、定期考核、该开除时开除」。

13.6个人投资者的现实约束

干净的 PIT 数据、历史成分股、逐笔行情，一年可能几万到几十万。免费数据有坑。

交易成本

没有机构费率，没有交易所返佣，融券成本高，做空工具少。

容量

资金小意味着很多策略「不值得做」——固定成本占比太高。

时间

你有本职工作。每天能投入 1–2 小时，和全职团队的差距是结构性的。

但也有优势：你不需要每季度向投资人交代，可以承受更长的回撤期； 你可以做小容量、高 alpha 的策略；你可以自由选择不交易。 这些优势指向同一个方向：低频、小容量、逻辑清晰、成本敏感。

给个人的最优解

大概率不是「做一个高频量化基金」，而是：核心仓位用低成本指数基金， 卫星仓位用 1–2 个你能完全解释的策略。这样你的收益不依赖单一策略， 你的精力也不会被交易耗尽。先把「不亏大钱」做好，再谈超额收益。

13.7本章陷阱清单

  • 用盈亏评价决策，而不是用过程。
  • 没有交易日志，或者日志只记结果不记理由。
  • 在亏钱时临时改变规则。
  • 连续盈利后加大杠杆。
  • 没有事先定义退役条件。
  • 把「回撤」当成「策略失效」，在最低点关掉系统。
  • 用生活必需资金交易。
  • 同时跑五个策略，每个都只投一点点，结果无法归因。

REQUIRED = ["date", "symbol", "open", "high", "low", "close",

def load_panel(path: str) -> pd.DataFrame:
    df = pd.read_parquet(path)
    missing = set(REQUIRED) - set(df.columns)
    if missing:
        raise ValueError(f"缺少字段: {missing}")

    # 关键：价格必须已复权（后复权），否则收益是错的
    assert df["close"].gt(0).all(), "存在非正价格"
    return df


def tradable_mask(df: pd.DataFrame, min_list_days: int = 250) -> pd.Series:
    """可交易过滤：非 ST、非停牌、上市满一年、有成交。"""
    listed_long_enough = (df["date"] - df["list_date"]).dt.days >= min_list_days
    return (~df["is_st"]) & (df["volume"] > 0) & listed_long_enough

14.3第二步：信号

signal.py
import numpy as np
import pandas as pd


def build_signal(df: pd.DataFrame, lookback: int = 252,
                 skip: int = 21, vol_cut: float = 0.70) -> pd.DataFrame:
    df = df.sort_values(["symbol", "date"]).copy()
    g = df.groupby("symbol")

    # 12-1 动量：过去 lookback 日收益，跳过最近 skip 日
    df["mom_12_1"] = g["close"].shift(skip) / g["close"].shift(lookback) - 1

    # 波动率：过去 60 日收益标准差（年化）
    df["ret_1"] = g["close"].pct_change()
    df["vol_60"] = g["ret_1"].transform(
        lambda s: s.rolling(60).std() * np.sqrt(252)
    )

    # 横截面排名（每个日期内）
    df["mom_rank"] = df.groupby("date")["mom_12_1"].rank(pct=True)
    df["vol_rank"] = df.groupby("date")["vol_60"].rank(pct=True)

    # 剔除高波动（最高的 30%）
    df["eligible"] = df["vol_rank"] <= vol_cut

    # 最终分数：动量排名，行业中性化
    df["score"] = df["mom_rank"]
    df["score"] = df.groupby(["date", "industry"])["score"].transform(
        lambda s: s.rank(pct=True)
    )
    return df
行业中性化的作用

如果不做行业中性，动量策略会系统性地超配当年最热的行业（比如 2020 年的白酒、 2023 年的 AI）。这会让策略变成「行业 bet」，而不是「选股 alpha」。 中性化之后，你在每个行业内部选最强的股票，行业暴露被大幅削弱。

14.4第三步：组合

portfolio.py
import pandas as pd


def build_target(signal: pd.DataFrame, top_n: int = 30,
                 max_weight: float = 0.05) -> pd.DataFrame:
    """每个调仓日选前 top_n 名，等权，单票上限 max_weight。"""
    rows = []
    for date, g in signal.groupby("date"):
        g = g[g["eligible"] & g["mom_12_1"].notna()]
        if len(g) < top_n * 2:
            continue
        picks = g.nlargest(top_n, "score")
        w = min(1.0 / top_n, max_weight)
        for _, row in picks.iterrows():
            rows.append({"date": date, "symbol": row["symbol"], "weight": w})
    return pd.DataFrame(rows)

注意 w = min(1/top_n, max_weight)：如果 top_n = 30，等权是 3.33%， 低于 5% 上限，所以实际上限不起作用。如果 top_n = 10，等权是 10%，就会被压到 5%， 此时总仓位只有 50%，剩下的现金是一个隐性的防御。

14.6第五步：归因——它到底在赚什么钱

attribution.py
import numpy as np
import pandas as pd
import statsmodels.api as sm


def factor_regression(strategy_ret: pd.Series, factors: pd.DataFrame) -> pd.Series:
    """把策略收益对市场/规模/价值/动量回归，看 alpha 是否显著。"""
    df = pd.concat([strategy_ret.rename("r"), factors], axis=1).dropna()
    X = sm.add_constant(df[factors.columns])
    model = sm.OLS(df["r"], X).fit(cov_type="HAC", cov_kwds={"maxlags": 5})
    out = model.params.copy()
    out["alpha_t"] = model.tvalues["const"]
    out["r2"] = model.rsquared
    return out


def yearly_returns(equity: pd.Series) -> pd.Series:
    return equity.resample("YE").last().pct_change().dropna()

典型的结果会长这样：市场 beta 0.85、动量暴露 0.3、alpha 年化 2.1%（t = 1.2）。 翻译成人话：这个策略 80% 的收益来自「持有股票」这件事本身， 动量只贡献了一点点，而且统计上不显著。

如果 alpha 的 t 值小于 2

不要急着调参数。先问：是样本太短、还是逻辑不成立、还是被成本吃掉了？ 三种情况的处理方式完全不同。样本太短 → 延长数据；逻辑不成立 → 换逻辑； 成本吃掉 → 降低换手。盲目调参只会让你离真相更远。

F期权速览

期权值得单独占一节，因为它是唯一一种「损益非线性」的基础工具。 股票、期货都是线性的：涨 1 块赚 1 块。期权不是——它让你可以用有限的风险， 表达对「波动率」而不是「方向」的观点。代价是它比股票复杂一个数量级。

个人最容易踩的坑

卖出期权收权利金看起来像「稳定收租」：连续 20 个月每月赚 1%， 第 21 个月亏掉 40%。这是典型的负偏策略，夏普很高，尾部很厚。 如果你要卖期权，必须同时回答：我的最大损失是多少？我有没有对冲？仓位占多少？

学习路径建议：先理解损益图与内在价值/时间价值，再学 Black-Scholes 的直觉 （不是推导），最后用模拟盘做 50 笔买方交易，体会 Theta 的衰减。 在没有搞清楚 Gamma 之前，不要碰卖方。

H20 个常见问题

这些问题来自真实的读者和初学者。答案很短，但每一条背后都有前面十几章的内容支撑。

关于入门

1. 需要多少启动资金？
学习阶段用「亏光也不影响生活」的金额，通常 1–5 万足够暴露所有执行问题。 资金太小（几千块）时，固定成本占比过高，学不到真实的成本结构。

2. 要不要学 C++ 或低延迟？
除非你要做日内或做市，否则不需要。日频策略的瓶颈是想法和数据，不是微秒。 把学 C++ 的时间用来做 100 次诚实的回测，回报高得多。

3. 技术指标（MACD、KDJ）有用吗？
它们是有用的特征，不是有用的策略。单独用几乎没有 alpha， 但作为多因子模型里的一个输入，可能贡献一点点信息。别把它们当圣杯。

4. 要不要读金融工程硕士？
如果你想做机构量化，有帮助；如果你只想管好自己的钱，投入产出比很低。 这本书 + 一份干净的数据 + 两年的实盘记录，比一个学位更能说明问题。

5. 应该做股票还是期货？
新手从股票或 ETF 开始：成本结构干净、数据质量好、不会被杠杆一夜清零。 期货适合已经能稳定盈利、并且理解基差与展期的人。

关于研究

6. 需要多少年数据？
日频策略至少 5 年，最好包含一轮完整的牛熊。少于 3 年，你连一个像样的回撤都没见过。

7. 为什么我的回测和实盘差这么多？
按概率排序：① 前视偏差；② 成本低估；③ 成交假设不现实；④ 幸存者偏差； ⑤ 市场结构变了。逐条排查，通常前两条就能解释 80% 的差距。

8. 用现成框架还是自己写？
第一遍自己写——你必须知道框架在哪些地方骗你。写完再用成熟的框架做交叉验证。 直接上手框架的人，通常不知道自己的回测为什么好看。

9. 策略需要多复杂？
越简单越好。复杂度应该来自「对市场的理解」，而不是「模型的层数」。 一个能用三句话解释清楚的策略，比一个黑箱更容易维护，也更容易判断何时失效。

10. 机器学习值得学吗？
值得，但优先级低于数据质量和验证设计。先用线性模型跑通全流程， 再考虑 GBDT。深度网络在日频、小样本的场景里，通常是负资产。

关于实盘

11. 一个人能同时跑几个策略？
2–3 个，且逻辑要不相关。超过这个数，你无法对每个策略的失效做出及时判断， 也无法在出问题时定位原因。

12. 要不要加杠杆？
先证明你在无杠杆下能稳定盈利两年，再考虑。杠杆放大的是波动， 而波动拖累是平方级的。1.5 倍杠杆看似温和，回撤会放大到 2 倍以上。

13. 怎么判断策略失效了？
区分三件事：正常回撤（在历史分布内）、执行问题（滑点突然变大）、逻辑失效（假设被证伪）。 只有第三种需要退役。前两种需要的是耐心和排查，不是关掉系统。

14. 亏损时怎么调整心态？
不靠心态，靠规则。事前写好最大回撤、单日亏损上限、退役条件； 触发时执行，不讨论。你在压力下做出的判断，大概率比冷静时差。

15. 高频交易个人能做吗？
基本不能。你需要托管机房、交易所会员、极低费率、以及一个团队。 个人在速度上的竞争，等于用自行车参加 F1。

关于职业与长期

16. 应该全职做交易吗？
先问三个问题：你有 24 个月的生活费吗？你的策略在扣除生活开支后还能复利吗？ 你能承受连续一年没有收入吗？三个都是「是」，再考虑。

17. 怎么看别人的策略或跟单？
看三样东西：最大回撤、收益归因、以及「他为什么愿意公开」。 一个真正有效的策略，容量有限，通常不需要卖课。

18. 第一年应该设定什么目标？
不是收益率，是过程指标：完成 50 次回测、写 100 篇交易日志、 跑通一次完整的实盘流程、把最大回撤控制在预设范围内。收益是结果，不是目标。

19. 需要每天盯盘吗？
低频策略不需要。盯盘的最大危害不是浪费时间，是让你忍不住干预。 把执行自动化，每天只看一次对账和告警。

20. 学完这本书，我就能赚钱了吗？
不能。这本书能让你不亏得莫名其妙，并在机会出现时认得出它。 剩下的，需要你自己在市场里待够时间——而活下来，本身就是最大的优势。

写在最后

这本书里没有一个能让你立刻赚钱的「圣杯」。它给你的是一套判断力： 判断一个策略值不值得做、一个回测可不可信、一次亏损是运气还是错误。 这套判断力不会让你每次都赢，但它会让你在输的时候输得少，在赢的时候知道为什么。

市场会一直在那里。你不需要抓住每一次机会，你只需要在少数几次真正属于你的机会里， 下注足够重，并且活着等到它兑现。
